## 1. 什么时候发、怎么发

- 每天 **07:00** 由 Molly 在私聊里发。用户可以在设置里改时间、关闭。
- 先发一条 Molly 的开场气泡（第 8 节），紧接着发简报卡片。
- 简报是一种新的消息类型 `daily_brief`，每天只发一条。
- **简报的“一天”从发送时间算到第二天的发送时间**，不是从 0 点到 24 点。例：简报 07:00 发，那么 11月4日 07:00 到 11月5日 06:59 之间的事，都放进 11月4日 的简报。用户把发送时间改成 08:00，范围就变成 08:00 到第二天 07:59。
  - 例：11月5日凌晨 06:00 有比赛，它属于 11月4日 的简报（第二天 07:00 那份发出来时比赛已经开始了）。
- 发出之后数据有变化（用户点了“确认”、缴了费、新加了日程），**同一张卡片原地更新**，不重新发一张。
- 用户当天还没打开 App，简报就留在聊天里；打开时显示的是最新状态。
- 没有任何内容（所有板块都空）时，照样发：只有抬头（日期和天气），开场气泡用第 8 节的“空”类。

## 2. 卡片整体

- 卡片是 Molly 发的一条**消息**，不是弹窗：宽度和气泡最大宽度一致，圆角 12px，底色和对方气泡同一个颜色变量，**无边框、无阴影、不透明**。
- 卡片**没有标题**，不写“今日简报”四个字。
- 结构：抬头 + 7 个板块，**顺序固定**。没内容的板块整块不显示，它前面的分割线也不显示。
- 板块之间用头发丝分割线：0.5px，左右各留 16px，颜色用玻璃弹窗分割线那个变量。
- 每个板块内边距 16px。板块名 12px / 600，次要文字颜色。
- 正文 14px；第二行说明 12px，次要文字颜色。

### 2.1 折叠

- 每个板块名的右边有一个**折叠箭头**：只有两条边的 V 形箭头（和任务页展开箭头同一个图标），14px，次要文字颜色。
- **默认全部展开。** 点板块名这一整行（或箭头），这个板块收起来，只剩板块名这一行；再点一下展开。
- 箭头方向和任务页保持一致：收起时朝下，展开时朝上。展开、收起有 200ms 的高度过渡，箭头同时旋转。

- 折叠状态按“这一条消息 + 这个板块”记住：关掉聊天再打开，还是用户上次的样子。第二天的新简报全部重新默认展开。
- 点了待定、缴费按钮，卡片原地更新时，不改变折叠状态。
- 板块名这一行是一个 `button`，带 `aria-expanded` 和 `aria-controls`。
- 周报用同一套折叠规则（见《周报-需求文档-给Codex》第 8 节），两边共用一个组件。

## 3. 抬头

两行，都是 14px，第一行加粗：

```
11月4日 周三 · 深圳
22–27° 多云，下午 3 点后有阵雨，带伞 · 限行尾号 3
```

- 第一行：`{月}月{日}日 周{X} · {城市}`。
- 第二行：`{最低}–{最高}° {天气}` + 一句提醒（来自下表）+ 出行信息（有才写）。用 ` · ` 隔开，**不要放大温度**，不要天气图标。
- 天气提醒只能从下表选一条，没有命中就不写：

| 条件 | 提醒 |
|---|---|
| 某个时段降水概率 ≥ 50% | {时段}有{阵雨 / 小雨 / 大雨}，带伞 |
| 全天下雨 | 全天有雨，带伞 |
| 最高温 ≥ 35° | 高温，少在外面待 |
| 最低温 ≤ 5°，或比昨天低 8° 以上 | 降温，多穿一件 |
| 空气质量 ≥ 150 | 空气差，出门戴口罩 |
| 大风预警、台风 | {预警名}，尽量别出门 |

- 出行信息（只在用户登记了车、而且城市当天有限行时写）：`限行尾号 {X}`。
- 天气接口：建议和风天气，密钥放 `.env.local` 的 `WEATHER_API_KEY`。没配置或请求失败时，第二行不显示，简报照发。
- 城市：第一次发简报前，Molly 在私聊里问“你在哪个城市”，下面两个胶囊按钮：“用当前定位：{城市}”“我自己输入”。之后可以在设置里改。

## 6. 各板块细则

### 6.1 待定

**进待定的唯一标准**：用户选完之后，**会改变今天或接下来的日程**。选完不影响日程的事（挑礼物、看候选人、看推荐）不进待定，在聊天里办。

只有两种：

| 类型 | 文字写法 | 按钮 |
|---|---|---|
| 改动 | 直接写改动本身，不写是谁建议的 | 确认、暂不 |
| 二选一或多选一 | `{事情}（{N} 选 1）` | 去选 |

改动的写法库（模型只能套这些格式）：

| 改动 | 写法 | 例 |
|---|---|---|
| 挪日期 | `{事}挪到{明天 / 周X}` | 腿部训练挪到明天 |
| 挪时间 | `{事}改到 {时间}` | 遛狗改到 21:00 |
| 换方式 | `{餐次}吃{外卖 / 食堂 / 外面}（{要求}）` | 晚餐吃外卖（减脂） |
| 取消 | `今天不{事}` | 今天不训练 |
| 加一件 | `加{事}` | 加拉伸 15 分钟 |

- 只有专业智友或 Molly 能提待定。
- **能按规则自动处理的，不进待定**：例行事项有顺延规则时直接顺延，在日程里打“顺延”标签，不问用户。例：加班到 20:00，晚上的遛狗按规则自动顺延到 20:30。
- 塞不进上面两种格式的事，一律不进待定，只在日程里写一行。
- 超过 3 条：只放最影响今天的 3 条，其余由对应智友在私聊里问。

### 6.2 日程

**每一行的结构**（每行固定两行高，第二行没内容也留着位置，保证每行高度一样，不挤）：

```
[时间 40px]  [主行文字] [标签]                    [负责人头像 22px]
             [第二行说明，没有就留空]
```

- 行与行之间间距 12px。
- **时间**：`HH:MM`；没有具体时间的写 `上午 / 下午 / 晚上 / 全天`。排序：全天 → 从发送时间开始按时间先后；上午排在 09:00 前面，下午排在 14:00 前面，晚上排在 19:00 前面。
- **过了零点的事**（在第二天发送时间之前）排在最后，时间列写两行：上面 `HH:MM`，下面一行小字 `明天`（和第二行说明对齐）。例：`06:00 / 明天`。
- **负责人头像**：每一行都有。专业的事显示对应专业智友（陈年、柳智敏、赵一帆），其他都显示 Molly。点头像或整行，跳到这个智友的私聊，并自动引用这一行。头像悬停显示名字，不写名字。
- **不出现“我”“你”**，不加多余的话（不写“昨晚备好的”“我挑了”）。

**主行文字只能用下面的模板：**

| 类别 | 模板 | 例 |
|---|---|---|
| 宠物 | 遛狗 {n} 分钟 / 喂{宠物名} / 带{宠物名}洗澡 / 给{宠物名}驱虫 | 遛狗 30 分钟 |
| 吃饭 | {早餐 / 午餐 / 晚餐 / 加餐}：{菜名} | 午餐：番茄牛腩饭 |
| 吃饭（不自己做） | {餐次}：外卖 / {餐次}：外面吃 / {餐次}：食堂 | 晚餐：外卖 |
| 补剂、药 | {名称} {剂量} | 维生素 D 1 粒 |
| 喝水 | 喝水 {n}ml | 喝水 2000ml |
| 训练 | {部位}训练 / 跑步 {n} 公里 / 拉伸 {n} 分钟 / 散步 {n} 步 | 腿部训练 |
| 睡觉 | 上床睡觉 | 上床睡觉 |
| 快递 | 快递 {n} 件{今天 / 明天}到 | 快递 2 件今天到 |
| 家政 | {保洁 / 维修 / 保姆}上门 / 预约{保洁 / 维修} | 保洁上门 |
| 接送 | 接{人} / 送{人} | 接爸妈 |
| 工作影响 | 加班到 {时间} / 出差 · {城市} / 早会提前到 {时间} | 加班到 20:00 |
| 出行 | {航班号 / 车次} · {出发地}→{目的地} | G1234 · 深圳北→广州南 |
| 采购 | 去{超市 / 菜场}买菜 | 去菜场买菜 |
| 缴费、证件 | 不放日程，分别在缴费、近期板块 | — |
| 其他 | 用户原话里的事，压到 10 个字以内，只留名词和动词 | 上坟 |

**第二行说明只能从这 6 种里选一种：**

| 类型 | 写法 | 例 |
|---|---|---|
| 地点 | {地点} | 小区驿站、深圳北站 |
| 时机 | 随{早餐 / 午餐 / 晚餐} / 饭前 / 饭后 / 睡前 / 空腹 | 随早餐 |
| 时长 | 约 {n} {分钟 / 小时} | 约 2 小时 |
| 改动原因 | 因{原因}，原定 {时间} | 因加班，原定 19:00 |
| 份量 | {n} {份 / 杯 / 碗} | 2 份 |
| 空 | 留空（位置保留） | — |

**标签（主行文字后面，小号、浅底）只有 5 种：**

| 标签 | 什么时候 | 样式 |
|---|---|---|
| 每天 | 每天都有的例行事项 | 次要文字色 |
| 每周X | 每周固定某天的例行事项 | 次要文字色 |
| 新增 | 今天临时加的 | 强调色加粗 |
| 顺延 | 按规则自动往后挪的 | 强调色加粗 |
| 改期 | 用户在待定里确认改过的 | 强调色加粗 |

**例行事项**：用户说一次（“每天早上遛狗半小时”），以后每天自动出现。字段见第 9 节 `Routine`。顺延规则例：遛狗 = 下班后 30 分钟；吃药 = 不顺延。

### 6.3 采购

**卡片里每张采购单一行：**

```
今日采购                                 [清单]
今明两天的食材
```

- 不写“几样”，数量放在弹窗里。
- **标题**只有三种：今日采购 / 本周采购 / 周{X}采购。
- **第二行说明**从下面 11 条里选，最多 2 条，用顿号连起来（例：本周的食材、日用品补货）：

| # | 说明 |
|---|---|
| 1 | 今明两天的食材 |
| 2 | 本周的食材 |
| 3 | 下周的食材 |
| 4 | 日用品补货 |
| 5 | 宠物用品 |
| 6 | 家居、家具 |
| 7 | 工具、五金 |
| 8 | 数码、家电 |
| 9 | 衣物、鞋包 |
| 10 | 药品、保健品 |
| 11 | 送人的礼物 |

**点“清单”弹出采购单**（玻璃弹窗，按《前端与智友体验改版》第 4 节）：

```
今日采购                              [复制] [关闭]
今明两天的食材 · 8 样
──────────
蔬果
西红柿                                     3 个
西兰花                                     1 颗
──────────
肉蛋奶
...
──────────
按赵一帆今明两天的菜单算好，冰箱里已有的土豆没算进去
```

- 标题 16px / 600；下面一行 `{说明} · {N} 样`。
- 右上角两个图标按钮：复制（复制图标）、关闭。点复制，把清单按下面的纯文本格式复制到剪贴板，toast 提示“已复制”：

```
今日采购（今明两天的食材）
蔬果：西红柿 3个、西兰花 1颗、青椒 2个
肉蛋奶：鸡胸肉 1斤、鸡蛋 1盒
...
```

- 分组固定 12 个，只显示有东西的组，顺序：蔬果、肉蛋奶、粮油调料、零食饮品、日用、宠物、家居家具、工具五金、数码家电、衣物鞋包、药品保健、礼物。
- 每样东西一行：左边名称，右边数量（次要文字色）；快用完的消耗品在数量后面加 ` · 还剩 {n} 天`。
- 最下面一行写来源，只能用这几种：
  - `按{智友名}{今明两天 / 本周}的菜单算好，冰箱里已有的{东西}没算进去`
  - `按用量算，快用完了`
  - `按聊天里说的整理`
  - 多个来源时用 `；` 连起来
- 采购单从哪来：
  1. 专业智友的菜单 → 自动算出食材，减掉用户说过冰箱里有的；
  2. 用户在聊天里说（“冰箱就剩一个土豆了，今天要去买菜”“周六要买螺丝刀和置物架”）；
  3. 例行消耗品按用量推算（狗粮、纸巾、洗衣液），快用完时自动加进来。
- 买完：用户在弹窗里勾掉，或在聊天里说“买完了”，这张单从简报里消失。

**Molly 在聊天里说采购的话**（Molly 的风格：短、冷、空格代替逗号、不加标点和表情）：

| 场景 | Molly 说 | 后面跟 |
|---|---|---|
| 用户说今天要去买菜 | 今天要买这8样 土豆不用买 | 采购单卡片 |
| 消耗品快用完 | 狗粮还剩3天 加进周六的单了 | 无 |
| 新菜单出来 | 下周的食材加进单子了 12样 | 采购单卡片 |
| 用户说要买别的东西 | 加上了 | 无 |
| 用户说买完了 | OK | 无 |

### 6.4 缴费

**每一行：**

```
物业费                                   [缴费]
明天到期
```

- 第一行：费用名称。第二行：`{相对时间}{动作}`，只写这一句，不加别的说明。
  - 动作只有三种：到期 / 自动扣费 / 还款。
  - 相对时间按第 7 节。
  - 例：明天到期、3天后到期、明天自动扣费、11天后还款。
- 3 天内（含今天）到期、扣费、还款的，第二行用危险色；其余用次要文字色。
- 用户告诉过金额才显示金额，写在动作后面：`明天到期 · ¥89`。

### 6.5 进度

要好几步才能办完的事。用户说了以后，Molly 把它拆成不超过 5 步。

```
狗狗打疫苗                                 1/3 步
▓▓▓▓░░░░░░░░
下一步：选时间预约
```

- 第一行：左边事情名，右边 `{已完成}/{总数} 步`（次要文字色）。
- 第二行：进度条，高 5px，圆角，填充用强调色，底用分割线色。
- 第三行：`下一步：{下一步要做的}`（12px 次要文字色）。
- **没有按钮**，只给用户看进度。
- 全部完成的那天显示一次（进度条满），第二天消失。
- 常见事项的步骤模板（写成配置，不在里面的由 Molly 现拆）：

| 事项 | 步骤 |
|---|---|
| 宠物疫苗 | 查医院 → 预约时间 → 去打针 |
| 办护照 | 查材料 → 网上预约 → 去出入境拍照办理 → 取证 |
| 车年检 | 查检测站 → 预约 → 去检测 |
| 体检 | 选机构和套餐 → 预约 → 去体检 → 拿报告 |
| 搬家 | 定日期 → 约搬家公司 → 打包 → 搬 → 办地址变更 |
| 找保洁 | 定需求 → 约人 → 上门 |

### 6.6 近期

用户说过的、快到的日子。内容直接用用户的说法，不预设固定项目。**没有按钮。**

```
妈妈生日                           11月6日 周五 · 2天后
车年检到期                         11月10日 周二 · 6天后
护照到期                          2027年4月3日 · 5个月后
```

- 左边：事情（14px），用户原话压缩到 10 个字以内。
- 右边：`{日期} · {相对时间}`（13px 次要文字色），日期和相对时间按第 7 节。
- 按日期从近到远排。
- 什么时候开始出现在简报里：

| 类型 | 提前多久开始显示 |
|---|---|
| 生日、纪念日 | 3 天 |
| 车年检、保养 | 14 天 |
| 身份证、护照、驾照、签证到期 | 3 个月 |
| 考试、出行、搬家、面试 | 7 天 |
| 用户自己说的其他事 | 按用户说的；没说就 3 天 |

- 当天过完就消失。
- Molly 已经开始帮着办、拆成了步骤的事，从近期移到进度。

### 6.7 关注

- 用户感兴趣的、在这份简报范围内（发送时间到第二天发送时间）发生的事：比赛、新片上映、开售、演唱会开票。
- 一件一行：`{今天 / 今晚 / 明早} {HH:MM} {事}`，例：`今晚 20:00 LPL 决赛`、`明早 06:00 欧冠决赛`。
- 最多 2 行，没有按钮。
- 来源：智友记住的用户兴趣 + 实时知识（见现有《实时知识接入方案》）。

## 7. 日期和时间的统一写法

整张简报（包括缴费、近期）都用这一套：

| 场合 | 写法 |
|---|---|
| 今年的日期 | `{月}月{日}日 周{X}`，例：11月6日 周五 |
| 跨年的日期 | `{年}年{月}月{日}日`，不写星期，例：2027年4月3日 |
| 相对时间：当天 | 今天 |
| 相对时间：第二天 | 明天 |
| 相对时间：2–59 天 | {n}天后，例：2天后、6天后 |
| 相对时间：60 天及以上 | {n}个月后（向下取整），例：5个月后 |
| 时刻 | HH:MM，24 小时制 |

- 不用“后天”“还剩”“还有”“X 天以后”这类说法。
- 缴费和近期的“今天 / 明天 / N天后”按日历日期算；日程和关注的范围按第 1 节的“一天”算。
- 数字和“天”“个月”之间不加空格。

## 8. Molly 的开场气泡

- 每天简报卡片前面，Molly 先发**一条**气泡。
- 风格按 Molly 的对话 Skill（`modes/secretary.md`）：短、冷、能一个词就一个词，**用空格代替逗号**，不加句号、引号、表情；可以叫“老大”。
- 所有开场句写在配置文件 `npc-skills/skills/zhiyu-dialogue/npcs/molly/brief-openers.json` 里，程序按下面的规则挑，**不让模型现编**。
- **不重复**：同一句话 7 天内不重复用；连续两天不用同一类里的同一句。

### 8.1 按什么挑

从上往下，命中第一条就用那一类：

| 优先级 | 条件 | 类别 |
|---|---|---|
| 1 | 今天是用户生日 | 生日 |
| 2 | 待定 ≥ 1 条 | 待定 |
| 3 | 缴费里有今天或明天到期的 | 到期 |
| 4 | 日程里有“顺延”或“新增” | 有改动 |
| 5 | 天气提醒命中下雨、高温、降温、空气差、预警 | 天气 |
| 6 | 今天是周六或周日 | 周末 |
| 7 | 今天是周一 | 周一 |
| 8 | 日程 ≥ 10 条 | 满 |
| 9 | 所有板块都空 | 空 |
| 10 | 以上都不是 | 普通 |

### 8.2 句子库

`{N}` 用汉字：一件、两件、三件。`{费用}` 用缴费里最急的那一项的名称。

| 类别 | 句子 |
|---|---|
| 待定 | 早 {N}件事等你定 / 早 先定{N}件事 / 老大 {N}个待定 / 早 {N}个待定 先决定一下 / 早 有{N}件要你拍板 |
| 到期 | 早 {费用}明天到期 / 早 {费用}今天到期 / 早 先把{费用}交了 |
| 有改动 | 早 今天有改动 / 早 今天的排法变了 / 早 改过了 看一眼 |
| 天气 | 早 带伞 / 早 多穿一件 / 早 今天热 / 早 今天别出门了 |
| 周末 | 周末也上班的只有我 / 早 周末的 / 周末 照样发 |
| 周一 | 周一 老大 / 早 新的一周 |
| 满 | 早 今天满的 / 今天事多 早 |
| 空 | 早 今天没安排 / 早 今天空的 / 早 |
| 普通 | 早 / 早 今天的 / 今天的安排 / 早 都排好了 / 老大 今天的 |
| 生日 | 生日快乐 这句免费 / 早 生日 今天少排点 |

- 天气类按命中的提醒选对应的句子：下雨 → 带伞；降温 → 多穿一件；高温 → 今天热；预警 → 今天别出门了。
- 交付时把这张表原样写进配置文件，用户以后会自己加句子。

## 9. 数据模型

```ts
interface DailyBrief {
  date: string;                 // YYYY-MM-DD
  opener: { category: OpenerCategory; text: string };
  header: { city: string; weather?: WeatherLine; traffic?: string };   // traffic: 限行尾号 3
  pending: PendingItem[];        // 待定，≤3
  schedule: ScheduleItem[];      // 日程
  shopping: ShoppingList[];      // 采购，≤3
  bills: BillItem[];             // 缴费
  progress: ProgressItem[];      // 进度，≤3
  upcoming: UpcomingItem[];      // 近期，≤5
  interests: InterestItem[];     // 关注，≤2
}

type OpenerCategory = 'birthday'|'pending'|'due'|'changed'|'weather'|'weekend'|'monday'|'busy'|'empty'|'normal';

interface WeatherLine { low: number; high: number; text: string; tip?: string }  // tip 只能取 3 节的提醒库

interface PendingItem {
  id: string;
  kind: 'change' | 'choose';
  text: string;                  // 按 6.1 的写法库生成
  ownerId: string;               // 提出的智友（不显示，用于执行）
  apply: ScheduleChange;         // 确认后对日程做什么
  choiceId?: string;             // kind=choose 时对应的选择卡
}

interface ScheduleItem {
  id: string;
  time: string;                  // 'HH:MM' | '上午' | '下午' | '晚上' | '全天'
  category: 'pet'|'meal'|'meal_out'|'supplement'|'water'|'training'|'sleep'|'parcel'|'housekeeping'|'pickup'|'work'|'travel'|'shopping'|'other';
  text: string;                  // 主行，只能由 6.2 的模板生成
  sub?: { kind: 'place'|'timing'|'duration'|'reason'|'amount'; text: string };
  tag?: '每天' | `每周${string}` | '新增' | '顺延' | '改期';
  ownerId: string;               // 'molly' | 'chen-nian' | 'liu' | 'zhou-chef'
  routineId?: string;
}

interface Routine {
  id: string;
  template: string;              // 例：'遛狗 {n} 分钟'
  params: Record<string, string | number>;
  repeat: 'daily' | { weekdays: number[] };
  defaultTime: string;
  postpone?: { after: 'off_work'; minutes: number } | null;   // null = 不顺延
  ownerId: string;
  sub?: ScheduleItem['sub'];
}

interface ShoppingList {
  id: string;
  title: '今日采购' | '本周采购' | `周${string}采购`;
  notes: string[];               // 6.3 说明库里的 1–2 条
  groups: { group: ShoppingGroup; items: { name: string; qty: string; daysLeft?: number }[] }[];
  sources: string[];             // 6.3 的来源句
  done: boolean;
}

type ShoppingGroup = '蔬果'|'肉蛋奶'|'粮油调料'|'零食饮品'|'日用'|'宠物'|'家居家具'|'工具五金'|'数码家电'|'衣物鞋包'|'药品保健'|'礼物';

interface BillItem {
  id: string;
  type: string;                  // 对应 6.4 费用清单的一行
  name: string;
  action: '到期' | '自动扣费' | '还款';
  dueDate: string;
  amount?: number;
  button: '缴费' | '充值' | '续费' | '还款' | '管理';
  link?: string;
  paid: boolean;
}

interface ProgressItem { id: string; name: string; steps: string[]; done: number }

interface UpcomingItem { id: string; text: string; date: string; kind: 'birthday'|'anniversary'|'vehicle'|'document'|'event'|'other'; showFrom: string }

interface InterestItem { id: string; when: string; text: string }
```
