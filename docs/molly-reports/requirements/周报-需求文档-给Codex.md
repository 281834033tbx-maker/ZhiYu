- 本文档里的所有内容一次性全部做完，做完后统一交付，不要分批停下来等确认。
- 本文档**替换**《前端与智友体验改版-给Codex》里第 13 节“周报与月报”。**月报本期不做**，那一节里月报的内容全部作废。
- 周报和《今日简报-需求文档-给Codex》是一对：**简报安排今天要做的事，周报总结这一周的结果**。周报里不放安排、不放待定、不放按钮。
- **颜色你自己定**：全部沿用现有聊天界面的颜色变量，和今日简报保持一致，不新增任何颜色值。
- 字号、字重、圆角、分割线按《前端与智友体验改版-给Codex》第 2–4 节；卡片样式和今日简报完全一样。
- 数据结构按第 9 节，以后接真实数据时只换数据源。

## 1. 什么时候发、范围怎么算

- 默认**每周日 21:30** 由 Molly 在私聊里发。用户可以在设置里改成别的星期几和时间，或者关闭。
- 先发一条 Molly 的开场气泡（第 7 节），紧接着发周报卡片。每周只发一条。
- **周报的“一周”从上一次发送时间算到这一次发送时间**，不是周一到周日。例：每周日 21:30 发，那么 11月1日（周日）21:30 到 11月8日（周日）21:29 之间的数据，算进 11月8日 的周报。用户改了发送时间，范围跟着变。
- 和今日简报同一个逻辑：简报的“一天”是从发送时间算到第二天的发送时间。
- 周报是**快照**：发出后内容不再变（折叠状态除外）。

## 2. 卡片整体

- 和今日简报一样：Molly 发的一条消息，宽度和气泡最大宽度一致，圆角 12px，底色和对方气泡同一个颜色变量，**无边框、无阴影、不透明**，**没有标题**。
- 结构：抬头 + 9 个板块，**顺序固定**。没内容的板块整块不显示，它前面的分割线也不显示。
- 板块之间用头发丝分割线：0.5px，左右各留 16px，颜色用玻璃弹窗分割线那个变量。
- 每个板块内边距 16px；板块名 12px / 600，次要文字颜色；每个板块名右边有折叠箭头（第 8 节）。
- **每一行的格式**（评语除外）：

```
[项目，14px]                          [数值，14px / 600]
[说明，12px 次要文字色，没有就留空但保留位置]
```

- 每行固定两行高，第二行没内容也留着位置；行与行之间间距 12px。
- 周报里**没有按钮**。只有评语可以点（第 5.9 节）。
- 字号全部是 14 / 12，不放大任何数字。

## 3. 抬头

两行，都是 14px，第一行加粗：

```
11月2日–11月8日
体重 −1.4斤 · 离目标还差 6.2斤
```

- 第一行：`{起}–{止}`，日期写法按今日简报第 7 节（今年只写月日，跨年写年月日），不写星期。
- 第二行：这周最重要的一个结果，按下表顺序取第一个能用的：

| 优先级 | 条件 | 写法 | 例 |
|---|---|---|---|
| 1 | 用户有目标，且目标指标这周有变化 | {指标} {变化} · 离目标还差 {n} | 体重 −1.4斤 · 离目标还差 6.2斤 |
| 2 | 某个领域这周计划全部完成 | {领域}全部完成 | 训练全部完成 |
| 3 | 有要紧的事 | {n} 件要紧的事 | 2 件要紧的事 |
| 4 | 都不是 | 这周没有大变化 | 这周没有大变化 |

- 只给大概的数，不列明细。
- 每日简报默认**不放**账本；用户明确说“每天告诉我花了多少”时，才在简报里加一行“昨天花了 ¥126”（正式上线时做）。
- 数据来源（正式上线时做）：手机版在用户单独授权后读取支付通知和银行短信自动记账（安卓）；苹果手机靠用户分享截图或快捷指令。消费记录属于敏感个人信息，打开记账前必须单独弹窗征得同意。本期演示数据写死。

### 5.8 追踪（用户点名才有）

- 用户说“每周告诉我 XX”，就加一项；说“不用看了”，就去掉。
- 写法：项目 = 用户要看的东西；数值 = `{数字}{单位}`；说明 = `{明细} · 比上周 ±n`。
- 例：`加班 · 2次 · 周三、周四 · 比上周 +1`。
- 常见的：加班次数、喝酒次数、游戏时长、看书页数、陪家人次数，以及用户说的任何次数或时长。

### 5.9 评语

```
[头像 22px]  [名字 12px / 600 次要文字色]
             [一句话 14px]
```

- 顺序：有计划的专业智友在前（陈年、柳智敏、赵一帆……），这周和用户聊过天的陪伴智友在后（夏夏、徐小曼、何嘉伟），**Molly 不写**。
- 专业智友：一句话，说这周的情况 + 下周的一个具体调整。
- 陪伴智友：一句朋友会说的话，不打分、不布置任务，遵守对话 Skill 的规则。
- 情绪系统：对用户冷淡的智友只写一句很短的；在生气静默中的智友这周不写。
- 点任何一条，跳到这个智友的私聊，并自动引用这句话。

## 6. 数字和时间的写法

- **右边数值**：数字和单位之间不加空格（166.2斤、6.8小时、3/4次、18/21顿、2次）。
- **说明里的变化**：`比上周 +n / −n`（负号用“−”）；时间用“早 / 晚 n分钟”；时长用“多 / 少 n小时”。
- 金额：`¥1,860`，千位加逗号；估算的前面加“约”。
- 日期、相对时间：按今日简报第 7 节。

## 7. Molly 的开场气泡

- 风格按 Molly 的对话 Skill（`modes/secretary.md`）：短、冷，空格代替逗号，不加句号、引号、表情。
- 句子库写在 `npc-skills/skills/zhiyu-dialogue/npcs/molly/report-openers.json`，程序按规则挑，**不让模型现编**；同一句 4 周内不重复。

|---|---|---|
| 1 | 有要紧的事 | 周报 有{N}件要紧的 / 周报 先看要紧的 |

## 8. 折叠（周报和今日简报都用）

- 每个板块名的右边有一个**折叠箭头**：只有两条边的 V 形箭头（和任务页展开箭头同一个图标），14px，次要文字颜色。
- **默认全部展开。** 点板块名这一整行（或箭头），这个板块收起来，只剩板块名这一行；再点一下展开。
- 箭头方向和任务页保持一致：收起时朝下，展开时朝上。
- 展开、收起有 200ms 的高度过渡，箭头同时旋转。
- 抬头不能折叠。
- 折叠状态按“这一条消息 + 这个板块”记住：关掉聊天再打开，还是用户上次的样子。新的一份简报或周报，全部重新默认展开。
- 今日简报点了按钮、原地更新内容时，不改变折叠状态。
- 无障碍：板块名这一行是一个 `button`，带 `aria-expanded` 和 `aria-controls`。

## 9. 数据模型

```ts
interface WeeklyReport {
  range: { from: string; to: string };      // 按第 1 节的发送时间计算
  opener: { category: 'urgent'|'progress'|'allDone'|'low'|'normal'; text: string };
  headline: string;                          // 按第 3 节
  blocks: ReportBlock[];                     // 只放有内容的，顺序按第 4 节
  comments: ReportComment[];
}

interface ReportBlock {
  id: 'urgent'|'body'|'training'|'diet'|'cooking'|'skincare'|'ledger'|'tracking'|string;  // 以后的专业板块用智友领域 id
  name: string;                              // 要紧 / 身体 / 训练 ……
  ownerIds: string[];
  rows: ReportRow[];
}

interface ReportRow {
  itemKey: string;                           // 对应第 5 节项目库里的一项
  label: string;                             // 左边项目
  value?: string;                            // 右边数值（要紧没有）
  note?: string;                             // 第二行说明
  danger?: boolean;                          // 要紧为 true
}

interface ReportComment {
  npcId: string;
  name: string;
  text: string;
  kind: 'professional'|'companion';
}

interface FoldState { messageId: string; collapsedBlockIds: string[] }   // 简报和周报共用
```
