## 4. 弹窗统一：透明玻璃 + 头发丝分割线

参考现在的智友资料卡（头像点开的那张）。它已经是对的方向，所有弹窗都按它统一。

### 4.1 哪些算弹窗

`theme-glass.css` 里已经列出的全部（设置、退出、宠物、副本、各种菜单、右键菜单、表情面板、动态通知、@ 菜单、任务选择、私聊设置抽屉、群设置抽屉、toast、图片查看器的菜单和转发），再加上：
- 发起群聊、转发消息（`group-create-dialog`、`message-forward-dialog`）
- 早报设置（`morning-reminder-settings`）、实时语音设置（`realtime-speech-settings`）
- 专业任务详情（`professional-task` 的弹窗）、今日任务弹窗
- 个人资料卡（`self-profile-card`）

逐个检查上面每个弹窗，都要用同一种材质：`background: var(--zy-glass-fill)`，边框 `var(--zy-glass-border)`，`backdrop-filter: blur(24px) saturate(125%)`，阴影用 3.2 的“浮层”。弹窗自己写死的底色（`#fafafa`、`#fafaf8`、`#fff` 等）全部去掉，改用玻璃。模态弹窗后面的遮罩沿用现有的 `--zy-glass-backdrop` + `blur(5px)`。

### 4.2 分割线：头发丝

- 线宽 0.5px，颜色 `var(--zy-glass-line)`。不用黑色，不用 `#eff0ed`、`#f0f0f2`、`#e3e5dd` 这类写死的灰。
- **左右留白**：弹窗和资料卡左右各留 24px，右侧抽屉左右各留 20px。线不能从边拉到边。
- 普通屏（`devicePixelRatio < 2`）上 0.5px 可能不显示：用 `1px` 线加 `transform: scaleY(.5)`，或用 `1px` + `var(--zy-glass-line)`，二选一，保证两种屏幕都看得到、都很细。
- **只在分组之间画线。** 同一组里的行和行之间不画。例如资料卡：头部 | 备注、状态、个性签名 | 动态圈 | 添加来源 | 底部操作，每两组之间一条线。
- 确认弹窗（清空、删除、退出）的底部按钮：上方一条通栏的头发丝线（这里允许从边到边），两个按钮中间一条竖的头发丝线，按钮高 48px。

### 4.3 文字层级：所有弹窗只用这 6 种

| 层级 | 字号 / 字重 | 颜色（已有变量） | 用在 |
|---|---|---|---|
| 大标题 | 20 / 600 | `--zy-ink` | 资料卡里的人名 |
| 标题 | 16 / 600 | `--zy-ink` | 弹窗标题、抽屉标题、确认弹窗的问题 |
| 正文 | 14 / 400 | `--zy-ink` | 左边的项目名（备注、状态、个性签名、动态圈、添加来源）、右边的内容、按钮文字、开关名 |
| 辅助 | 13 或 12 / 400 | `--zy-glass-muted` | 账号、地区、添加来源的值、说明文字、版本号、右侧箭头前的当前值（“07:00”“深圳”） |

## 5. 状态

### 5.1 规则

- 每个智友有一个状态库，状态由程序按当天生活脚本自动更换，用户不能改，也**不能点开**，只显示。
- 数量：陪伴智友（夏夏、徐小曼、何嘉伟）每人约 20 条，专业智友（陈年、柳智敏、赵一帆）每人约 12 条，Molly 4 条（在线、整理周报中、排明天的日程、盯进度）。
- 每人每天换 3–5 次，同一小时内不换两次，每条最多挂 24 小时。
- 智域事件（`智域事件与八卦系统`）可以临时换上事件状态，比如陈年“写检讨中”，挂 1–2 天，期间优先显示。
- 生气静默期间，显示“暂时不想说话”，静默结束恢复原状态。
- 状态文字 2–8 个字，不带表情，不带句号。
- **不准出现**：表示没空或不在的状态（睡觉中、忙、勿扰、晚点回、离线），因为智友永远秒回；说自己在真实地方、玩真实游戏的状态（“在打排位”“在迪士尼”）；Molly 的生活类状态。

### 5.2 状态库文件

放在 `npc-skills/skills/zhiyu-dialogue/npcs/<id>/status.json`，Molly 放在 `npcs/molly/status.json`：

```json
{ "items": [ { "text": "在追番", "slots": ["evening", "night"], "weight": 2 } ] }
```

`slots` 取值 `morning / noon / afternoon / evening / night`，用来和生活脚本的时段对应。按下面的示例和人设补满到上面的数量，交付时单独列出全部状态，等用户审阅：

| 徐小曼 | 写稿中、卡文了、在看吃播、读一本悬疑、交稿了，放空 |
| 何嘉伟 | 晨跑、在看季度数据、面试新人、复盘中 |
| 陈年 | 带课中、练腿日、下午打球、研究新动作 |

### 5.3 显示位置

1. **聊天顶部名字下面**：现在显示的是个性签名（`chat-header.tsx` 的 `bio`），改成显示状态。Molly 现在显示的“您的智能机器人助手（闲聊200）”也换成她的状态。正在输入时，这一行临时变成“正在输入…”（见第 11 节）。

## 8. 报错与失败

1. **不白屏**：在应用根部和每个主页面（消息、智友、任务、动态）各加一个错误边界。出错时只显示那一块的兜底（“这里出了点问题”+“重新加载”按钮），其他部分照常可用。错误详情只写日志。
2. **不用系统弹窗**：`app.tsx` 里两处 `window.alert` 换成玻璃样式的 toast。
3. **不给用户看技术报错**：所有 `error.message` 不再直接显示。建一个错误文案映射表（`lib/user-facing-errors.ts`），技术错误统一翻译成人话：
   - 网络 / 服务没起来 / 模型超时 → “网络不太好，消息没发出去”
   - 余额、密钥、模型错误 → “出了点问题，稍后再试”（详细原因只写日志）
   - 保存失败 → “没保存上，再试一次”
4. **发送失败**：像微信一样，气泡旁边一个小的重发图标（颜色用现有危险色），点一下重发。不弹窗。
5. **自动重试**：生成回复失败时先自动重试 1 次，第二次失败才显示重发图标。

- 其他页面（任务、动态）的空状态用一句该页负责人的话，比如任务页空：Molly 说“今天没安排，想做什么跟我说”。不出现“暂无数据”“暂无群聊”。

## 11. AI 提示与“正在输入”

### 11.1 AI 提示（三处）

1. **输入框下方常驻一行**：“智友由 AI 驱动，可能会出错，重要的事请自己再确认”，11px，颜色 `--zy-muted`，居中。私聊、群聊和桌面人物窗都要有。
2. **每个智友的第一次聊天**：聊天最上方显示一条居中灰色系统提示（12px，颜色 `--zy-muted`，不是气泡）：
   - 陪伴智友：“{名字}是智域的智友，由 AI 驱动。”
   - 专业智友：“{名字}是智域的专业智友，由 AI 驱动。建议很专业，但也可能出错；身体不适请先就医。”
   - Molly：“Molly 是你在智域的秘书，由 AI 驱动。”
3. **智友标识**：资料卡和聊天顶部的类型标识（`npc-type-badge`），悬停提示写“智友 · AI”或“专业智友 · AI”。

**连续使用提醒**：用户连续使用每满 2 小时，由当前正在聊天的智友用自己的口吻提醒一次（比如夏夏：“你跟我聊了两个多小时了诶，起来走走？”）。由程序计时触发，作为一条普通消息发出，不弹窗。这条消息不受“不用吃饭喝水睡觉安慰人”那条规则限制。

### 11.2 “正在输入”的节奏

替换 `lib/npc/delivery.ts` 里现有的 `deliveryTiming`（现在第一条最少要等 5 秒，太慢）：

- 用户发出后 0.5–1.5 秒（随机），开始显示“正在输入…”。
- 每条消息的打字时长 = `0.8 秒 + 字数 × 0.12 秒`，最少 1 秒，最多 4 秒。
- 只有一个表情，或只有一两个字（“嗯”“？”“好”）：0.6 秒。
- 一条发出后停 0.3–0.8 秒（随机），再显示“正在输入…”打下一条。
- 按人物调快慢（写在 `profile.json` 的 `typingSpeed`）：夏夏 0.8，陈年 0.9，赵一帆 1.2，何嘉伟 1.2，其他 1.0。打字时长乘以这个系数。
- 模型还没生成完时，一直显示“正在输入…”；生成好后按上面的节奏一条一条放出来。
- **显示位置**：聊天顶部名字下面那一行（平时显示状态的位置）临时变成“正在输入…”，颜色用 `--zy-nav-active`。消息列表里不再单独显示“对方正在输入中...”那一行。
- 群聊：顶部显示“陈年 正在输入…”，同一时间只显示一个人。
- 例：“瘦不了，这是健身圈最老的坑”（14 字）≈ 0.8 + 1.68 = 2.5 秒。

## 12. Molly 早报

- 默认每天 **07:00**（把 `morning-reminder-settings` 里的默认值 08:00 改成 07:00），用户可以在设置里改时间和城市。
- **城市**：第一次发早报前，Molly 在私聊里问“以后每天早上我给你发早报。你在哪个城市？”，下面两个胶囊按钮：“用当前定位：{城市}”“我自己输入”。定位用系统定位，没有权限时退回按 IP 判断城市，都不行就只给“我自己输入”。之后早报卡片右上角有“{城市} · 换城市”。
- **天气**：接一个国内天气接口（建议和风天气），密钥放 `.env.local` 的 `WEATHER_API_KEY`，没配置时早报照发，只是不显示天气块。
- **卡片内容**（从上到下，组和组之间用头发丝线，左右各留 16px）：
  1. 日期（16 / 600，例“11月3日 周二”）+ 右上“深圳 · 换城市”（12，`--zy-nav-active`）
  2. 天气：图标 + 温度区间（28 / 600）+ 一句话（12，辅助色，例“多云，下午 3 点后有阵雨，带伞”）
  3. “今天”（12 / 600，辅助色）：今天的任务和日程，每行左边时间（12，辅助色，宽 44px），右边内容（14）和来源（12，辅助色，例“陈年”“柳智敏的午餐计划”）。数据来自任务页的今天数据和日历。
  4. “需要你拍板”（有才显示）：专业智友待用户确认的选择，比如“陈年：晚上有雨，跑步改成室内单车？”+ 两个按钮。点按钮等于在对应智友那里做了选择。
- Molly 发卡片前先发一条气泡“早。今天的安排”。

## 13. 周报与月报

### 13.1 卡片样式（早报也用这套）

- 卡片是 Molly 发的一条**消息**，不是弹窗：底色用 `var(--zy-incoming)`（和对方气泡同色），圆角 12px，**无边框、无阴影、不透明**。这样一看就是 Molly 发来的，深色模式也会自动跟着变。
- 卡片宽度和气泡最大宽度一致（不超过 420px）。
- 内部分组之间用第 4.2 节的头发丝线：`var(--zy-glass-line)`，0.5px，左右各留 16px。
- 卡片里的正文用 `--zy-ink`，辅助文字用 `--zy-muted`（不是玻璃的变量），文字层级照第 4.3 节。
- 卡片里的进度条底色用 `var(--zy-glass-line)`，填充用 `--zy-nav-active`；次按钮底色用 `var(--zy-canvas)`。

### 13.2 周报

- **每周日 20:00**，Molly 在私聊里发。先发一条气泡“本周周报整理好了”，再发卡片。
- 内容（按 `claude/群聊玩法.md` 第一部分已确认的格式）：
  1. 标题“第 N 周周报” + 日期范围；有目标倒计时的，在右上角显示标签（例“伴郎冲刺 D-9”）
  2. 体重（周平均）和腰围，28 / 600 大数字，下面写“比上周 −1.4”
  3. 训练、按计划吃饭、带饭：每项一行“3/4 次 · 周三没练”+ 进度条
  4. 身体感受：睡眠、精力、酸痛
  5. 下周调整
  6. “团队的话（点一下直接回复）”
- 数据全部由程序从任务数据计算，不让模型算。没有记录的项写“本周没记录”。

### 13.3 月报

- **每月 1 号 09:00**，Molly 发，先发气泡“{N} 月的月报”。
- 内容：标题“{N} 月月报” + “整月计划完成 81%”；每周平均体重的柱状图（最后一周用 `--zy-nav-active`，其他周用浅色）；训练、按计划吃、腰围三个数字；本月拿下（里程碑）；下月重点；团队的话。

### 13.4 团队的话（周报、月报都有）

- 每个**参与了的**智友写一句，用自己的口吻，带头像和名字：
  - 专业智友：本周（本月）给用户布置过任务的，写这周的情况和下周的一个具体调整。
  - 陪伴智友：本周（本月）和用户聊过天的，写一句朋友式的话（不打分、不布置任务，遵守对话 Skill 的规则）。
  - 顺序：专业智友在前，陪伴智友在后。Molly 不写。
- 和情绪系统配合：对用户冷淡的智友只写一句很短的话；静默中的智友这次不写。
- 点某一条，跳到这个智友的私聊，并自动引用这句话。

## 14. 对话 Skill 改造

### 14.1 分层加载

现在每轮都会加载 `core/` 全部 13 个文件（约 4 万字）。改成三层：

1. **常驻核心**（每轮都读，总共 ≤ 4000 字）：说话立场的核心规则、标点语气表情、世界观、记忆、时间作息、知识边界的要点、危机的触发和处理要点、优先级。
2. **场景模块**（程序判断场景后才读）：
   - `10-群聊` 只在群聊时读
   - `11-主动消息与动态` 只在生成主动消息、动态时读
   - `09-图片与语音` 只在用户这轮发了图片或语音时读
   - `04-安慰` 只在意图是倾诉、难过时读
   - `03-梗与俗语` 只在陪伴模式读
   - `12-危机` 的完整版只在危机意图时读
3. **人物资料**：`profile`、`style`、`interests`、`examples` 不变。

压缩时不准丢规则的意思。交付时附一张对照表：原来的每条规则现在在哪一层、哪个文件。

### 14.2 去掉运行时不该读的内容

- 规则文件里的修改历史、日期、“覆盖旧资料”、“用户要求……”这类过程性文字，全部移到 `archive/`。
- `dialogue-skill.ts` 拼进提示词的开发用语（“不可变快照”“稳定人物ID”“DB”“coaxFactor”等）改成普通说法，或者删掉。

### 14.3 能用代码管的交给代码

下面这些不再只靠模型自觉，由程序在发出前检查：
- 句式黑名单（`core/01` 第二部分）命中 → 自动替换成表里的说法；替换不了就重新生成一次。
- 每次回复 1–4 条；用户让闭嘴、让滚时只发 1 条。
- 名字只能用第 7.2 节的正式名。
- 第 7.2 节的禁词不准出现在智友的话里。
- 朋友圈每天最多 2 条、间隔 2 小时、最多 9 张图，由 `moment-policy.ts` 控制，不写在提示词里。

### 14.4 规则换成示例

核心规则每一条配 1–2 个“错 → 对”的例子，优先用 `npcs/*/examples.json` 里用户亲手写的对话。纯禁令、而且已经有例子覆盖的条目删掉。

### 14.5 两处冲突的定论（写进核心规则）

1. **说完就停 vs 留话题**：默认说完就停，结尾不加邀约、叮嘱、总结。只有用户回得很短、话题快聊死的时候，才顺着抛一个相关的话题，一次一个，用户不接不追。
2. **生气静默**：静默期间，聊天顶部状态那一行显示“暂时不想说话”（见 5.1），其他规则不变（只回道歉和危机）。

### 14.6 生图合并成一套

- 把 `npc-candid-photo` 和 `chen-nian-visual-style` 合并进 `zhiyu-imagegen`：聊天里发的照片和朋友圈配图走同一个流程、同一套规则。
- 每个智友一个身份包：`npc-skills/assets/<id>/identity/`，放固定的脸部参考图（正面、侧面、半身）和外貌说明。生成任何含本人的图片都必须带上它。
- 素材库：`npc-skills/assets/<id>/library/` + `manifest.json`（每张图的场景、时间段、季节、标签、是否已审核）。生成照片前先从素材库里找匹配且已审核的图，找不到再实时生成。实时生成的图默认“未审核”，审核通过后进素材库。
- 生成的图片按国家规定加隐式标识（元数据里写明 AI 生成）。

### 14.7 朋友圈 Skill 瘦身

`zhiyu-moments/SKILL.md` 里的修改历史、日期和授权说明移到 `archive/`。频率和数量限制交给代码（14.3），提示词里只留“写这一条动态”需要的内容。

## 15. 每晚自动考试

新增 `npm run npc:exam`：

1. 读 `npc-skills/skills/zhiyu-dialogue/tests/测试题.md` 的全部题目，逐题发给对应的智友（私聊题、群聊题按题目要求），拿到回复。

   - 第 7.2 节禁词、叫错名字
   - 句式黑名单（`core/01` 第二部分）
   - 条数超过 4 条
   - 说自己去过、玩过、见过真实的地方或游戏
   - 题目里写明的检查点（测试题第七部分“标点和格式”每题都查）
3. 输出 `docs/qa/YYYY-MM-DD.md`：每个智友的分数、和上一次的对比、每处扣分的原话。
4. 每次修改 `npc-skills/` 后必须跑一次，交付时附上本次改造前后的两份报告。
5. 提供一个每天凌晨 3 点自动运行的定时配置（本机计划任务），默认关闭，写清楚怎么打开。
