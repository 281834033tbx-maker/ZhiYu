# 智域内测版部署与验收

更新：2026-11-16。当前默认开放账号注册和登录，无需邀请码；保留约 50 人邀请码内测的部署方式。运行入口是 **Node 生产服务**，不是 Vite 开发服务器，也不是原 Cloudflare 静态托管。

## 交付范围与当前边界

手机入口 `/mobile`，后台入口 `/admin`。默认 `ZHIYU_INVITE_ONLY=0`（未设置也关闭），用户注册独立账号后用账号和密码登录，注册须确认已满 18 岁；资料同样存到服务器，普通用户不会成为内部管理员或认领旧桌面数据。

以后部署阿里云时，在私有环境文件中设置 `ZHIYU_INVITE_ONLY=1` 并重启服务，即恢复原邀请码界面，同时关闭普通注册和密码登录接口。两种模式均保留认证、账号隔离和后台权限；不是共享匿名账号。开关不删除既有账号、邀请码、聊天和任务。切换后已有有效会话不被清空；普通账号退出后需切回开放模式才能用密码登录。

在邀请码模式下，同一个邀请码恢复同一个服务器账号；登录凭证是 HttpOnly Cookie，内测业务资料不保存在浏览器 localStorage 或 IndexedDB。邀请码是账号的登录凭证，不能交给其他人共同使用；系统识别邀请码对应的账号，不核验现实中的个人身份。

代码提供邀请码、账号隔离、服务器状态、真实事件、后台权限、问卷与导出。部署不会自动生成创始人密码、50 个正式邀请码、聊天、任务、问卷答案或统计样本。所有既存桌面账号首次迁移时标为内部账号；新的普通注册账号和普通邀请码账号默认计入统计。

已用全新临时应用根目录验证 7 位智友的规则与知识库都从随包的 npc-skills 加载，不依赖开发机全局 Skill；已核查 public/npc-skills/scripts 共 717 个文件没有指向开发机的符号链接。Docker 镜像模板尚未在真实 Docker 主机实际构建验收。

本轮使用临时库进行隔离验收，**没有把桌面真实库、旧密钥或正式联系人数据打包，也没有公开上线**。两部真实手机、实际公网、真实麦克风/摄像头与第三方订单尚需上线后验收。语音、视频、外卖和分享等只统计原功能中实际发生且有对应事件的操作；某个入口可点击不等于已经具备真实通话、下单或平台接入能力。

## 一、准备与目录

需要一台能长期运行 Node 的服务器、HTTPS 域名、持久磁盘和模型服务凭证。代码要求 Node ≥22.13；下面的 Docker 模板使用 Node 24。没有安装 Python、模型权重或桌面 Codex CLI 的新服务器不会自动获得本地语音/生图能力。

建议只开 **一个应用进程和一个副本**，由 HTTPS 反向代理接入。当前 SQLite、后台排期和本地文件不适合多个独立副本各存一份数据；扩容前须另做共享数据库、媒体存储和作业锁。

应用工作目录至少要包含：

| 路径 | 用途 |
| --- | --- |
| `dist/server`、`dist/client`、`dist/beta` | 前端、RSC 和 Node 生产构建 |
| `node_modules`、`package.json` | Node 运行依赖 |
| `public` | 程序静态素材 |
| `npc-skills` | 智友规则、人物资料和资产 |
| `scripts` | 后台初始化与已有可选运行脚本 |
| `.npc-runtime` | **持久数据，不进入镜像或公开目录** |

`ZHIYU_DATA_ROOT` 指向以上有 public/npc-skills/scripts 的应用根目录；数据库实际在其 `.npc-runtime/state.sqlite`。只需要把 `.npc-runtime` 持久挂载，不要把整个应用根目录挂成空盘。

## 二、配置与本机启动

先在一份干净的部署副本安装、构建：

```sh
npm ci
npm run beta:build
```

把配置文件放在代码目录以外，并设为 `0600`。例如 `/etc/zhiyu/zhiyu.env`：

```dotenv
HOST=127.0.0.1
PORT=3100
ZHIYU_PUBLIC_ORIGIN=https://zhiyu.example.com
# 阿里云内测重新启用邀请码；当前开放版改为 0。
ZHIYU_INVITE_ONLY=1
NPC_TEXT_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_THINKING=disabled
DEEPSEEK_API_KEY=请在服务器填写真实凭证
```

上面的域名和凭证只是需要替换的占位符，不能原样上线。远程新服务器建议显式选择已配置的文字模型提供方；不配置时旧默认可能依赖桌面的 Codex CLI。音频、天气等使用已有对应提供方配置，不能复制桌面 `.env.local` 整包当作上线配置。

启动：

```sh
ZHIYU_ENV_FILE=/etc/zhiyu/zhiyu.env npm run beta:start
```

也可以通过操作系统环境变量设置 `ZHIYU_DATA_ROOT` 和 `ZHIYU_BUILD_ROOT`。`HOST` 默认 `127.0.0.1`、`PORT` 默认 `3100`；监听非本机地址时必须配置 HTTPS 的 `ZHIYU_PUBLIC_ORIGIN`。多个受信任公网源可用逗号分隔的 `ZHIYU_PUBLIC_ORIGINS`，仍建议保留一个主 `ZHIYU_PUBLIC_ORIGIN`。不要添加不受自己控制的域名。

开放注册按连接来源地址限制为每 15 分钟最多 100 次有效注册尝试，超出后返回 429；反向代理下多个用户可能共用此额度。系统不信任客户端自行填写的转发 IP。此限流是进程内保护，不能替代上线后的容量评估。

使用 systemd 等服务管理器维持进程，并正确转发 SIGTERM。`GET /healthz` 只表示 HTTP 服务存活；模型调用、外部媒体和硬件能力应另测。

## 三、Docker 部署

项目根目录已有严格白名单 `.dockerignore`。运行镜像不复制 `.npc-runtime`、`.env*`、Git、旧备份或 output。构建阶段生成不包含个人 Sites 项目编号的空托管配置，Node 构建不启用 Cloudflare 插件。

```sh
docker build -f distribution/beta/Dockerfile -t zhiyu-beta:local .
docker volume create zhiyu-beta-runtime
docker run -d --name zhiyu-beta --restart unless-stopped \
  --env ZHIYU_PUBLIC_ORIGIN=https://zhiyu.example.com \
  --env ZHIYU_ENV_FILE=/run/secrets/zhiyu.env \
  --mount type=bind,src=/etc/zhiyu/zhiyu.env,dst=/run/secrets/zhiyu.env,readonly \
  --mount source=zhiyu-beta-runtime,target=/app/.npc-runtime \
  -p 127.0.0.1:3100:3100 \
  zhiyu-beta:local
```

容器内部 `HOST=0.0.0.0`，宿主机端口仍只绑定本机回环地址。容器以非 root 的 node 用户运行；密钥文件必须允许该用户读取，例如授予匹配的只读组权限，避免为了解决权限而改成全员可读。命名卷由镜像目录初始化权限；若换成宿主机目录挂载，要先给容器 UID 1000 写入权限。

容器配置文件不要设置 `HOST=127.0.0.1`，否则覆盖容器监听地址。升级镜像时保留同一数据卷；不要执行删除数据卷的清理命令。

可选的本地 Python ASR/TTS、外部生图 CLI、权重和 GPU **没有包含在此基础镜像中**。只有完成对应部署与真实验证后，才向用户提供相应能力。

## 四、HTTPS 与反向代理

模板在 `distribution/beta/nginx.conf`，用于 Nginx 的 `http {}` include 目录。替换 `zhiyu.example.com` 和证书路径，执行 `nginx -t` 通过后再启用。应用只对反代开放本机端口。

反代必须保留用户实际的 Host 和 Origin，正确传递 WebSocket Upgrade，并关闭流式响应缓冲。不能在反代伪造 `Origin: http://localhost` 来绕过校验。HTTPS 公网登录 Cookie 带 Secure；麦克风等浏览器功能同样依赖安全上下文。

## 五、后台初始化与邀请码

在交互终端执行两次，分别设置创始人和投资人密码：

```sh
npm run beta:admin
```

Docker 使用：

```sh
docker exec -it zhiyu-beta npm run beta:admin
```

选择 `founder` 或 `investor`，输入不同的至少 12 位密码。密码不作为命令行参数、不回显；服务器保存的是加盐 scrypt 摘要，文件 `.npc-runtime/beta-admin-secrets.json` 权限为 `0600`。重新设置某个角色密码会使该角色旧会话失效。不要把真实密码、邀请码或模型密钥发到聊天、Git 或共享截图中。

创始人登录 `/admin` 后，在邀请码管理中填 `50` 批量生成。**完整邀请码只在本次生成回包中显示**，立即导出 CSV 并安全保存；数据库只保存摘要和遮掩尾号，以后无法从列表找回完整码。给真实样本发普通码；给本人、演示、验收用账号勾选内部标记，内部账号始终排除统计。

停用邀请码会撤销其已有登录会话，并拒绝再次登录；恢复邀请码不会恢复旧会话，需要重新登录。每个码始终对应原账号，不会因为换手机、换浏览器或清缓存重复开户。

投资人仅看只读编号、真实汇总和经打码的问卷内容，不能管理邀请码、查看备注或问卷专用联系方式。看板不显示聊天正文。

## 六、保存、并发与统计口径

浏览器状态先在内存中响应，再带账号和版本写入服务器。断网或保存失败会提示未保存并重试；存在同一字段并发修改时会提示选择版本。**出现未保存提示时不要直接关闭页面**；页面关闭时的小体积补发不能保证断电、断网或超大图片的最后改动已经落盘。

单条状态值上限 20 MiB，单账号状态上限 32 MiB，最多 2048 个键；这不等于全部服务器聊天/媒体空间上限。收藏图片仍限原 12 MB，转成 base64 后体积会增大。大图应减少尺寸，不能把上传成功提示当作服务器已保存；收藏保存流程会等待服务器确认。

会话以真实前台可见且窗口有焦点的时间累计；间隔至少 30 分钟才重新计会话。客户端异常关闭、断网或设备休眠期间不能可靠补时，程序不估算缺失时长。看板每 10 分钟重新拉取，问卷提交后统计可以通过刷新立即核对。

留存以北京时间自然日、服务器加入时间和真实打开事件计算。尚未到对应天数或没有有效分母显示“数据不足”。NPS 的 A/B 结果分开统计；问卷完成率按真实收到、真实提交人数计算，内部账号不进入分子或分母。

问卷 A 在加入满 7 天、B 在满 28 天后的首次有效打开排期，5 分钟后由服务器投递；错过当天不会伪造历史收到时间，下一次有效打开继续排期。避开北京时间夜间，24 小时未填最多提醒一次。草稿和提交均在服务器，未收到问卷不能提前填。

## 七、在线备份与恢复

### 在线数据库快照

不要在应用运行时只复制 `state.sqlite`：已提交记录可能仍在 `-wal`。提供的脚本使用 SQLite 在线 backup API；较早 Node 没有该 API 时使用一致性的 `VACUUM INTO`，并执行 `quick_check`。备份目标必须不存在。

```sh
umask 077
node distribution/beta/backup.mjs /var/backups/zhiyu/2026-11-15-state.sqlite
```

Docker 可先在持久卷中生成再复制到受保护的宿主机目录：

```sh
docker exec zhiyu-beta node distribution/beta/backup.mjs /app/.npc-runtime/backups/2026-11-15-state.sqlite
docker cp zhiyu-beta:/app/.npc-runtime/backups/2026-11-15-state.sqlite /var/backups/zhiyu/2026-11-15-state.sqlite
```

此脚本只快照主库 `state.sqlite`。通话转写另存在 `.npc-runtime/realtime-speech-history.sqlite`，也要备份；不能把主库备份当作全部语音历史备份。还要备份 `.npc-runtime` 下实际产生的用户媒体和后台密码摘要文件；模型凭证在外部密钥文件中单独保护。在线数据库快照只保证该数据库一致，不保证其他数据库及同时复制的所有媒体具有相同时间点。需要完整备份或可完整回滚的发布前备份时，先正常停止服务，再归档整个 `.npc-runtime`（含所有 SQLite、WAL 与附件）和配置，并记录镜像版本。

备份含私有聊天、记忆与问卷联系方式，应加密存储、限制权限、放到另一块磁盘或独立备份空间。定期用隔离目录演练恢复；只看到备份文件存在不算恢复验收。

### 恢复步骤

1. 正常停止应用，保留当前损坏/待回滚目录一份副本，避免覆盖唯一现场。
2. 使用相匹配的发布版本。把备份的完整 `.npc-runtime` 恢复到持久位置；若使用在线数据库快照，则在服务停止时替换 `state.sqlite`，并将旧库的 `state.sqlite-wal`、`state.sqlite-shm` 移到保留目录，不能让旧 WAL 附着到恢复库。
3. 恢复用户媒体、后台密码摘要文件和外部配置；恢复正确属主，密码文件保持 `0600`。不要把别的用户桌面数据库并入内测库。
4. 在隔离环境执行 SQLite `PRAGMA quick_check`，再启动服务。用已存在的内部邀请码验证跨设备历史、任务与问卷草稿；不生成补数。
5. 确认恢复时间点和缺失范围后再对外开放。恢复快照会回退快照之后的新资料，不能宣称零数据损失。

## 八、上线前验收清单

这些操作应在**隔离验收环境或标为内部的测试账号**完成；正式招募后不得改真实样本的加入时间或补录统计。

- [ ] HTTPS `/mobile` 在 320px、390px 和常见安卓宽度可操作。开放模式显示注册/登录且没有邀请码输入；注册不确认成年时前后端均拒绝。邀请码模式显示邀请码、年龄说明、成年勾选与进入按钮，不勾选同样拒绝，普通注册/密码登录接口返回 403。
- [ ] 分别以 `ZHIYU_INVITE_ONLY=0` 和 `1` 重启，核界面与接口一致，已有账号和数据不丢失；开放注册的两个普通账号互相看不到资料，后台仍须管理员单独登录。
- [ ] 邀请模式下，两部真实手机分别用两个内部码登录；发不同聊天、修改档案与计划，互相看不到。退出 A 再登录 B，收藏、草稿、任务和偏好也不串号。
- [ ] 邀请模式下清浏览器缓存，用同一码重登；聊天、记忆、档案、计划、周报与收藏恢复。该码在另一部手机登录仍是原编号。
- [ ] 关闭并重启应用服务，数据仍在；升级容器后继续挂同一持久卷，历史不丢。
- [ ] 用真实支持的聊天入口发 10 条消息，重复网络重试不重复计数；一项实际可用的通话结束后，其真实时长在 10 分钟内入看板。未配置通话时明确记录“未验收”，不伪造事件。
- [ ] 在隔离库测试普通样本和内部样本；内部账号操作不进入全部汇总、排行、留存、问卷指标及导出。
- [ ] 投资人界面和接口均不能取得邀请码备注、完整码、联系方式；问卷原话中的手机号、微信号打码，CSV 同样受权限保护。
- [ ] 隔离账号加入时间移到 7 天前，首次前台打开后 5 分钟收到 Molly 问卷 A；草稿退出再进入仍在，提交后结果和 NPS 正确更新。28 天的 B 同样验证，提醒最多一次。
- [ ] 同账号两端改不同字段能合并；同字段冲突提示选择，不静默覆盖；断网有保存提示，重连后落盘。延迟到达的 A 请求不能写到 B。
- [ ] 停用码后所有设备旧会话失效；普通内测用户不能修改全局模型、语音密钥或调用调试/历史导入接口。
- [ ] 无真实样本时指标不补数；未成熟留存显示“数据不足”；时间均按北京时间。
- [ ] 从在线备份在独立目录恢复成功，核对媒体、后台角色和同一码账号恢复。

完成以上真实环境验收后，再给 50 位内测用户发普通邀请码。保留部署版本、验收日期与尚未实现能力清单；不要把临时库通过、界面截图或一个可点击按钮称为全部实机能力验收通过。
