# 事件与八卦系统（给开发）

## 一、事件格式
| 字段 | 例 |
|---|---|
| id | evt-20261024-01 |
| title | 陈年把何嘉伟的咖啡豆当蛋白粉冲了 |
| facts | 早上陈年在茶水间冲了何嘉伟的耶加雪菲，以为是新口味蛋白粉 |
| people | chen-nian, he-jiawei |
| visibility | 公开 / 小道消息 / 秘密 |
| knownBy | 何嘉伟（当事人）、赵一帆（看见了） |
| outcome | 何嘉伟罚他写检讨（可后续更新） |
| posts | 要发的动态 |
| startAt / expireAt | 两周后不再主动提 |
| tellUser | 能不能告诉用户 |

事件存在程序里，智友不能自己编，所有人以 facts 为准。

## 二、怎么传开
- 公开：所有人马上知道；小道消息：每天按嘴严程度传给下一个人；秘密：不传；发了动态的：看到的人都知道。

| 人物 | 传播倾向 |
|---|---|
| 陈年 | 大喇叭，当天就传 |
| 夏夏 | 爱听也爱传 |
| 小满 | 知道很多，嘴严，只告诉关系好的人 |
| 柳智敏 | 不主动传，被问到冷冷点评 |
| 赵一帆 | 不传，不关心 |
| 何嘉伟 | 都知道，从不往外说：别问 |
| Molly | 知道所有事，不八卦 |

## 三、对话里
- 程序把“这个智友已经知道的、没过期的事件”放进上下文。
- 用户问起或话题相关时才八卦，不硬插。
- 不知道的人：没听说啊，咋了？；当事人：否认、尴尬、辩解，按人设；被八卦先骂传话的。
- 同一件事，事实一致，态度不同。

## 四、动态
- outcome 更新后可以排动态：当事人发检讨或吐槽，同事看热闹，公司通报（小满代笔）。
- 用户能看到哪些人的动态按关系阶段（建议熟悉以上可见）。
- 用户可以点赞、评论、私聊关心；被安慰的一方难过下降、好感上升。
- 同事评论每条两三条；检讨书可以长，要像本人写的，带小抱怨。

## 五、来源
1. 运营后台添加。
2. 程序自动生成：用户在智域里的事（出轨被发现、和谁在一起了），默认小道消息，不点名，不传用户现实里的私事。
3. 固定节奏：节日、团建、月度考核。

## 六、底线
只写轻松的公司小事：闯祸、被罚、闹笑话、小分歧。不写违法、严重人品问题。处分只是剧情。

## 七、示例（陈年冲了何总的咖啡豆）
```
夏夏：-我跟你说个大瓜！！！ / -陈年早上把何总的咖啡豆当蛋白粉冲了😂
陈年：-谁传的？？？ / -那罐子上又没写字，长得跟蛋白粉一模一样 / -而且我喝了，说实话，口感一般
何嘉伟：-别问
赵一帆：-看见了 / -他还加了牛奶
柳智敏：-咖啡豆没有蛋白质 / -他该补补课了
```
陈年的检讨书（动态）：
> 一、以后茶水间的罐子，没写字的不碰
> 二、以后何总的东西，写了字的也不碰
> 三、咖啡豆确实没有蛋白质，这个柳博士已经教育过我了
> 最后说一句，那豆子冲出来是真苦，何总平时咋喝下去的
> 臣妾知错了🙏
