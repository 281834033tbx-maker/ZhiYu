## 2026-10-12 私聊选择消息接入历史

现有六位普通NPC与独立Molly私聊支持 `Part {type:"choice",text,options:string[]}`；每条2至6个选项，当前单选。模型只生成问题与选项，`selection {index,turnId,at}` 仅服务端在真实点击提交后填写。前端沿用原聊天气泡和正文样式，点击经同账号/当前会话校验，以原选项文本作为引用原问题的真实用户消息继续原回复队列，并持久保存已选状态。

不把choice转成步骤勾选、任务委托、计时或自动建群操作；实际意图仍按原流程判断。镜像入口只读，群聊本轮保持原协议。草稿、历史任务与私人关系不因新增控件而重置。来源与实现范围见[本轮记录](../../../../output/choice-chat-integration-20261012/user-requirement.json)；程序检查、合成隔离交互、正式模型语感与用户评价分别验收。

## 最小输入

| 输入 | 作用 |
| --- | --- |
| character_id、profile_version | 当前人物和有效配置；不按显示名猜身份 |
| user_id、branch_id、run_mode | 用户/分支隔离，明确模拟或生产；聊天文本不能自行切调试模式 |
| incoming_messages、recent_delivered | 本轮输入及近期已送达内容，区分实际素材与占位描述 |
| relevant_memory | 与当前问题相关、带来源和状态的记忆；不全量读全部NPC历史 |
| relationship_state | 正式程序提供的阶段、四项关系值、双方确认与最新边界 |
| active_tasks、life_state | 有效目标、条件、步骤/约定以及当前可信生活线索 |
| now、timezone | 可信时间，客户端/服务端明确时区；不把用户声称的时间用于绕过状态 |
| capabilities、tool_results | 真正可用的检索/计算/媒体/任务工具与结果、来源、时效 |
| proactive_eligibility | 主动任务才需要：用户主动聊天证据、正式阈值判定、配置版本、暂停和频控结果 |

未知字段保持未知。不能从旧演示数值补生产初值，也不能以缺人物生平为由拒绝能够可靠回答的普通问题。缺工具或时间不编状态。

主动阈值判定建议由程序给出`passed / failed / missing_configuration`。缺配置不能自行算通过；当前被动回应与专业帮助不等待这个判定。

## 建议输出

- `messages`：角色有序消息，每项代表一条消息；普通模拟逐条显示，不拼回长段`text`。独立`？`、`...`也保留为一项，专业信息按语义组织，不固定字数切割。程序模式采用实际要求的协议。
- `task_actions`：建议的任务步骤、条件核对或需执行动作，引用对应输入证据；不能自己宣布工具已执行。
- `memory_candidates`：建议新增/修正的事实、类型、来源和确定性，处理冲突，不直接覆写。
- `relationship_evidence`：真实相处事件及涉及熟悉/好感/信任/舒适的证据，通常不输出增减数值。
- `life_candidates`：符合确认人设的新轻量虚构生活，单独标记；未保存/送达不当成有效共同历史。
- `proactive_candidate`：可选主动内容、对应目的与有效资格引用；候选不等于发送或创建提醒。
- `debug_summary`：仅给操作者的简短依据/缺配置提示，不输出隐藏推理链，不混进角色消息。

只输出本轮需要的候选，不为了填满字段制造事件或关系变化。静默时消息数组为空；不能发一个“未回复”的角色气泡。

## 分工

| 部分 | Skill做什么 | 程序/工具做什么 |
| --- | --- | --- |
| 广泛回答 | 理解需求、选相关依据、组织帮助与人物表达 | 真实检索、计算、权限和结果检查 |
| 人物连续 | 保持人格、读有效生活与关系、提出合理生活候选 | 保存版本、生活事件与送达历史 |
| 记忆 | 提出有来源的记忆与修正 | 按人物/用户存取、纠错、撤回与并发处理 |
| 隐藏值 | 提出相处证据 | 用批准规则计分、去重、校验、保存阶段 |
| 任务 | 给步骤、根据反馈调整、提出约定 | 持久化进度、实际执行、计时与取消 |
| 主动联系 | 判断此刻有没有合适内容和人物意愿 | 核查双前提、暂停、作息、未回应与总频控，再决定发送 |

任务状态与同一套私人关系同时输入。任务帮助和已约定必要跟进不靠私人分准入；任务外主动必须核对用户已决定的两个前提。任务结束不继承无限主动权限。

专业问答本身不自动加全部正向值。诚实合作、尊重、独立判断与履约等真实人际证据可以影响关系；不能用机械提问、照做方案或不断夸赞兑换亲密。未回复不直接扣分。

高分只提供关系发展可能，不能替代恋爱路线、成年条件、双方意愿与明确确认。拒绝亲密不撤回正常帮助，用户也可以只做朋友或只求助。

## 一次主动发送前

程序先分任务必要互动和任务外聊天；后者核查用户主动聊天的有效证据及正式隐藏阈值。两项满足后，Skill结合人物生活、关系阶段和意愿准备候选；发送前再次核查最新暂停与频控，避免生成期间状态已变化。

资格不足、配置缺失、没有可说内容或用户暂停时，可以不生成/不发送。全员统一资格，不给陪伴人物额外绕过通道，也不替专业人物加第三个闲聊分。

接入时将用户边界保存为带来源消息、时间/版本、适用范围和当前状态的记录。阈值`passed`只是资格结论，不能覆盖更新的有效暂停。生成上下文与发送前状态冲突时先阻止该次发送，由程序重新读取/核对，不让模型选一个对发送有利的旧状态。暂停的恢复也要有符合范围的有效新表达，不因时间经过、高分或未回复自动解除。

“只停止私人闲聊”和“停止所有主动联系”范围不同；后者不默认保留任务消息例外。有有效提醒而用户表达范围不清时，先在当前互动明确约定/取消范围，未明确前不新增主动跟进。本建议是边界记录方式，不新增养成门槛或知识等级。

“用户主动聊天”是否包括纯专业提问、哪些值/阈值以及频率仍未定。当前没有真实提醒工具时，不对用户承诺到点会自动联系。应用内聊天资格不自动授予系统通知或其他渠道权限。
