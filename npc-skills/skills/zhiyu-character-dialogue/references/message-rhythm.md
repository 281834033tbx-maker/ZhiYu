# 短消息与气口分条

适用：普通NPC文字回复和多人对照展示。来源：旧通用规则G02、陈年2026-09-22拆句细则、[2026-09-23旧路由](../../../references/sources/expressive-modules-20260923/dialogue-routing.md.txt)，以及2026-10-05用户重申“整体段落不要特别长，要分开写”。

在内容组织时决定有序消息，按意思和气口自然发送。即时反应、具体态度、新细节和必要追问可以分别独立；不把所有句子挤成一段，再靠句末问号证明自然聊天。

2026-10-05后续用户指出候选仍为大长段：日常私聊要按真正的说话气口分成一条条短消息。一个段落里包含反应、关心、分享或新问题时，判断是否应分别发送；不只把长段落拆成几段小作文，也不每几个字机械切行。

短的是单段的气口与阅读负担，整轮回答可以长。涉及分析、完整方法、具体经历或复杂倾诉时，按语义充分展开；不将多气泡、清单或篇幅本身判为冗余。每条有新内容，重复和无关包装才精简，不把必要内容压成一两句后反问用户。

用`messages`保存顺序，每项对应一条消息。展示候选时保留边界，不能为了六人比较又拼回单个`text`。普通聊天短消息可以不用句末句号，问句和语气标点按意思保留；不靠删光标点装出随意。

2026-10-18用户明确全人物长话也要清楚分行：消息内的阅读层次统一执行[全人物文字排版](text-readability.md)，与本页独立消息的气口分条分别处理。该模块由普通人物与Molly各自入口共同加载，不把本页普通聊天示例一起复制给Molly。

- 一句“咋了”就够时只发一句，不补“你说”或固定第二条。
- 自然的“哈哈哈”“对啊”“太可爱了”可以独立或跟短句一起说，表达当下反应，不按模板补齐。邀请已说清时不附加采访式尾句，不因有多个模块就每个模块发一条。
- 有新内容才加下一条，不凑条数、不换词复述同一个意思，也不把用户刚回答的内容再总结一条作过渡。已知内容用于具体判断、实际安慰、必要确认或敲定结果时保留。短句习惯不等于短且干，更不等于只回嗯。
- 本轮关心、鼓励、收住玩笑或承认冒失已回应到位时，可以停。不要为了收完整而追加原则、自证、礼貌退场或关系安排；分成短句也不能掩盖这类模板组织。
- 情绪激动时可缩短句子、按实际气口分更多条；关心、商量和轻松分享也可分条。不把陈年个人密度参考强制推广给全员。
- 分条按语义，不逐句号切碎，不按字符数自动切，不拆断数字与单位、引用、步骤或代码。
- 内置小表情可以跟随文字或单独成条，图片表情包独立成条；校准图片示意清楚标记。小波浪～按人物和语境偶用，不统一替换标点或固定作结尾。
- 专业答案仍完整：结论、可执行部分、必要条件或追问按语义分成易读消息。复杂内容可有清单、表格或较长解释，但“完整帮助”不等于默认一整段独白，也不能为了短删条件。
- 模拟的是本轮有序消息，不编撤回、延时送达、打字节奏或真实发送成功。

不新增硬字数、气泡数或发言间隔。未来程序适配保留数组顺序与内容；旧解析器限制另行协调，本轮不自动改变App。
