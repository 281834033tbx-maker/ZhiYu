# 从今天的校准到真实产品效果

目标：用户既得到可靠帮助，也愿意继续与某个具体人物相处。Skill能提高行为一致性，人物受欢迎和产品留存仍需真实体验验证。

## 当前用户确定的训练顺序（2026-10-05）

用户明确“总共聊天里面分四步，基座是第一步”，要求先把第一步基座完全确定，再开始后续。当前只校准自然聊天基座与各人物在日常中的表达差异，继续确定气口分条、反应、表情、追问/停止及人格一致性；咨询与开导的专项训练留待后续，不因它们能检验共同能力而提前混入当前阶段。

这覆盖助手上一轮“现在一起调咨询与开导”的顺序建议。何嘉伟十题仅获初步认可，不认定第一步全部完成或自动进入下一步；基座的整体验收与单批案例认可分别记录。用户此条只明确第一步和先后顺序，本轮不自行补造后三步名称或重排既定阶段。

上述是进入本轮之前的阶段约束。下面早期闭环、专业问题和混合情绪等建议保留为历史/后续参考；训练顺序不删除人物已具备的专业知识，也不改变程序现有帮助、关系或媒体能力。

同日最新阶段更新：用户明确“咱们来进行下一步”，将Skill分为陪伴类和专业类，并询问何嘉伟作为陪伴型NPC下一步的位置与训练内容。当前允许进入何嘉伟的陪伴专项讨论，前面的基座沿当前版本作为后续校准基础；不把进入下一步扩为r5每句台词已获认可、全部人物基座定稿或App语感验收。用户的两类分工为明确要求，何仍可提供创业/工作等专业帮助，不改共享关系或专家问答目标。

本轮建议下一步先训练情绪承接与理性开导：识别倾诉和征求判断、回应具体痛处、了解必要经过后表达立场、用户只想吐槽时收住道理、用户听懂却仍难过时继续相处、被误解或遭用户反驳后调整。此安排是助手待校准建议，不声称此前已确定四步中后三步的名称。关系升温、连续记忆与主动分享可以后续分别校准，继续遵守既有关系/主动条件；本轮不创建新正式计分或调度规则。

同日随后用户认可情绪回应与多轮陪伴的训练方向，明确要求五类一次覆盖十五例，每例用户与何嘉伟各两轮，并先完整读取全部适用Skill。按本轮明确数量生成[十五组陪伴候选](../../zhiyu-companion-dialogue/references/he-jiawei-emotional-cases-20261005-r1.json)，覆盖受挫自否、亲友伤害、用户有错、只想倾诉与不接受回应。该请求覆盖早期少量场景展示建议；方向认可不等于新台词认可或App效果验收，保持各分支独立，后续反馈再最小更新陪伴互动或本人规则。

## 今天优先做的闭环

一件具体问题/心事 → 有用且符合人格的回应 → 用户追问、纠错或实践 → 人物调整 → 下次准确接续。它同时检验问答、人格、记忆与陪伴；不要只验一句开场白。

先使用何嘉伟与夏夏作对照：高冷/克制与开朗的表达差异，接受相同专业问题和混合情绪。已有小满、陈年的认可范围作为自然聊天基底，再迁移并抽检；不重新训练已有正确片段。

这是训练顺序建议，不改变六位的优先级、主体验或正式设定。用户同日已明确六组性格，见[最新人物配置](character-design.md)；周师傅成熟正经的方向已确定，具体措辞及柳职业等未定部分继续单独标记。

## 具体顺序与产物

| 步骤 | 做什么 | 可检查的产物 |
| --- | --- | --- |
| 锁定来源 | 确认最新产品要求、原基座与被覆盖的旧限制 | 来源表与冲突记录，本Skill已提供 |
| 提炼人物 | 从已有档案取行为与例外，补差异候选 | 两张样板行为卡，确认/候选分别标记 |
| 同题对照 | 用相同输入、资料和关系夹具连续追问 | 少量多轮对话，检查答题质量与人物区别 |
| 用户校准 | 用户指出好句、错句与行为问题 | 原场景、原回复、反馈原话及认可范围 |
| 最小修订 | 共性改基座，个性改个人卡，事件问题改场景/状态 | 可复用规则与针对性的复测场景 |
| 扩到六人 | 原场景加未见问题，保持独立生活与关系 | 六人对照结果；不要求回答逐字不同 |
| 隔离接入 | 协调门控、案例加载、消息格式和持久状态 | 合成会话实际模型/程序结果与回滚方案 |
| 小范围观察 | 真实用户体验后复盘 | 帮助效果、返回接续与人物偏好证据 |

完成文档和结构检查可以当天交付。真正语感须用户反馈，真实记忆与调度须实际程序验证；没有结果时写尚未完成，不能承诺今天全部NPC和所有未来人物都已训好。

## 用哪些场景

使用[八组多轮场景](../tests/scenarios.json)。正常问答、纯倾诉、混合需要、跨领域、意见分歧、任务失败、隔天接续与主动资格都要覆盖，测试上下文全部是合成夹具。

不要先写固定理想台词让人物背。为每场景明确有效事实、关系/任务、用户消息和可观察行为，再记录实际输出。新候选不自动进入用户认可库。

首次可只展示两个场景、每人少量连续轮次，避免让用户批改一整本。一次认可仅覆盖其指出的句子或行为，沉默与继续聊天不等于批准。

## 用户只需要指出问题，归类由助手完成

每条反馈保存日期、角色ID、规则/人物版本、原输入、有效关系、原回复、用户原话、认可片段、适用范围与复测场景。具体会话中的虚构用户资料不写进真实用户档案。

| 问题 | 修哪里 |
| --- | --- |
| 多人物都有的客服腔、机械续聊 | 共用自然聊天核心 |
| 所有人专业答案缺步骤或不可靠 | 共用问答/工具与结果检查 |
| 只有某人不像自己 | 个人行为卡及对应例外 |
| 同一标签在不同人物都写偏 | 对应人格模块，复核适用范围，不把单个人习惯直接推广 |
| 单个标签合适，但特定组合失真 | 组合规则或对应人物情境例外，不重写全部标签 |
| 关系突变、记忆串线、任务丢失 | 对应状态输入、保存/读取与程序校验 |
| 只有某一场景过度玩笑/说教 | 场景规则，不扩成全员永久禁令 |

修改后复测原问题，再用另一个相关人物或未见场景检查迁移。不要不断给总Skill堆关键词禁令来修补局部问题。

标签复用按[可组合人格模块](personality-modules.md)执行。优先校准标签而非逐个新增人物写整套示范；已验证组合可继承，新人物保留少量共同场景抽检。所有当前模块定义与主标签分配仍是助手设计，不因保存方案而成为用户认可。

2026-10-05用户采纳上一轮组合方向，要求沿用原10个问题，让六人分别回答。使用[60条同题候选](six-character-comparison-20261005.json)做本轮点评，不缩成两个样板人物。原何/夏十组候选全文保留在[历史回答](../../../references/sources/dialogue-ten-candidates-20261004.txt)；新候选均未获用户逐句认可，关系/生活/面试记忆为合成夹具，不保存为真实用户事实或生产人物记忆。后续反馈指向题号、角色及具体句子，再记录认可范围与最小修订层。

同日随后用户指出第一版没有充分应用独立问号/省略号、小脏话和短消息分条；原版只作批评对照，不再作为当前候选。使用[第二版60条候选](six-character-comparison-20261005-v2.json)，每个responses.messages元素对应一条消息。按[即时反应](reaction-markers.md)、[粗语](profanity-context.md)、[消息节奏](message-rhythm.md)检查实际内容与展示边界，不只检查文件里有没有写规则；不为演示配额化插入，每条具体新台词仍待用户点评。

## 怎样判断“人物有吸引力”

先看帮助是否准确、有用，用户能否采取下一步。再看用户是否自愿追问、隔次回来续同一件事、选择同一个人物，以及选择的具体理由。

可隐去姓名比较少量回答，询问辨认依据：选择理由、关心方式、语气节奏还是仅一个口头禅/emoji。目标是稳定的人物区别，不要求每句话都能被辨认，也不靠不同错误事实制造差异。

观察首次解决问题、次日/一段时间后的自愿回来、原任务接续、人物偏好以及主动消息被接续或被暂停的情况。定义测量窗口和分母后再计算；本Skill不自拟合格百分比，也不把聊天越长、消息越多或越亲密当成越成功。

“火起来”还取决于人物形象、响应速度、稳定性、进入聊天的方便程度与传播。可以从确实有用且好聊的样板积累用户愿意分享的片段；分享由用户明确选择，不自动公开私聊、用索取回应制造留存或保证爆火。

## 接入与发布

先保留旧有效版本及用户数据；在合成会话里验证新Skill、广泛问答门控和消息格式，再接记忆/任务/关系保存及主动发送检查。比较同条件旧/新结果，记录加载版本与实际延迟。

上线前分别验收：问答可靠、人物稳定、连续记忆、零分帮助、关系事件有证据、主动双前提/暂停、工具失败诚实、Molly隔离。不能用包结构PASS替代这些实际结果。

本轮已完成一次[独立代理设计演练](../tests/design-trial-20261004.json)：何嘉伟测试零值下的副业/营养回答、夏夏倾诉转求解、资格已过但用户暂停的主动候选。输出为代理模拟且未获用户认可，仅说明规则可以支持这些行为；人物具体取舍与语感仍待校准，不能当成实际App模型验收或作为认可few-shot使用。演练指出边界记录与暂停范围需要明确，相关建议已补入运行分工。

不要因为完成设计就自动修改App、发送消息、开启通知、计分或部署。用户已授权的具体后续接入按其范围完成，所需未定参数必须明确后再启用；文案设计和真实运行状态分开。

## 2026-10-05 有内容的长回复复测

用户要求重新走流程，允许长回复，并指出“你在干嘛”这类问题没有意义。[三组长内容场景](../tests/long-reply-cases-20261005.json)涵盖完整方案、明确时间点的工作困难和带具体限制的挫折倾诉。全部输入为合成夹具，无理想答案；五项内容判据是助手提议，不是已认可台词。

四个已有后端用`scripts/verify-long-content-20261005.mjs --live`跑实际builder、规则快照、检索、模型生成、复核和parser，保存草稿、复核改动与最终消息。链路通过、篇幅观察、内容评审、用户语感认可分别记录。400～900汉字仅作复杂场景观察，不是生产配额；必要分析、条件、步骤、取舍和有内容的陪伴应保留，不用空泛反问替代。何嘉伟/周师傅仍只做规则加载，不算已有AI后端。

## 2026-10-05 小满十题与逐项沉淀

用户最新范围为自然聊天基座，先只校准小满。获认可的每一大项反馈先查已有规则：共性更新核心/表达模块，专属语气更新小满模块，旧冲突按最新指示覆盖并保留依据；用户要求先看文字时，认可后再写。原则认可与具体新台词认可分开，不把助手合成案例写进真实记忆。

本轮[小满十题候选](xiaoman-base-cases-20261005-r3.json)使用当前同一完整适用规则快照，每题保留人物、合成称呼/关系、输入、messages与逐项检查记录。这里的完整使用指必要模块都加载且按当下语境判断，不意味着每题必须出现昵称、图片、故事、问号、小表情和～全部元素。问经过时用开放追问，具有关心或兴趣的问题保留；分享不自动变方法，温暖不自动变复读。

表情图片暂用明确内容示意，内置小表情直接显示；新候选为本聊天助手生成，独立内容评审不等于通过App/Codex后端逐题实跑。离线链路检查只证明加载、角色隔离、生成/复核同规则、缺模块失败和正文不因标题相邻被吞。具体语感仍由用户修改。

同日最新用户逐题批评r4并认可六类文字归纳，要求写入后生成十个新案例。使用[r5候选](xiaoman-base-cases-20261005-r5.json)继续校准：先审分享动机、具体伤心处和实际反应，问题须有自然好奇；保留人物观点/参与和口语，删刻意昵称、多余尾句及后台调整播报。不能仅因安慰、问句和表情都出现就判合格。助手此前pass与用户后来否定分别记录；本轮原则获认可不等于r5台词获认可。

后续r5获整批认可，r6多轮候选被逐项纠偏；用户明确认可四点总结和[r7七条重写](xiaoman-base-cases-20261005-r7.json)并要求写入。已把具体语气对照放入小满专属运行正文，不仅存档或加链接；共用机制按人物表达。检查实际回应能否让用户松一点、是否变成自证/顾虑/礼貌声明/总结，不能只核对字数或表达元素。第5、9已有认可保留，第6本轮未评价不提升状态；新增的未见场景仍需校准，不据此宣称所有App聊天稳定达到相同效果。
