# 人物主体验与专业特长标签

日期：2026-10-04。范围：本聊天的人物定位和 Skill 配置设计，不是 App 接入。用户已采纳同一套关系值＋独立专业任务状态、专业不设私人分数门槛、真实专业互动可以推动私人关系的方向；数字、门槛和程序仍未改。

## 当前用户设定与提案

用户明确小满主要是陪伴人物，并新补充做短视频、可以帮助用户做短视频；何嘉伟主要陪伴，专业方向是创业和工作问题。用户提出周师傅主要专业指导、同时陪伴的方向并询问评价。具体短视频/工作指导范围仍需细化，不把职业标签扩成全领域专家。

建议在内部用“主体验＋专业特长”表达用户的主线/副业想法。“主体验”是产品相处重心，职业/专业特长是人物实际能力，避免将陪伴称为人物职业或用主次否定另一种能力。

小满的“100%陪伴型”在本轮最新要求下表示主体验确定为陪伴，不表示不能帮忙。主次标签不是消息比例、字数比例、计分倍率或切换人格的指令。用户当前需要优先：陪伴人物接受了专业任务就认真完成；专业人物听到倾诉也可按自己的性格与关系回应。

## 标签怎样真正影响产品

主体验影响介绍与推荐、默认入口和本轮训练优先级；专业特长决定知识资料、可接受任务、能提供什么帮助及边界。主动行为仍区分任务/私人来源，受已确认配置和状态控制，不仅凭主体验决定频率。

界面可用一行介绍，如“小满 · 陪伴／短视频创作”“何嘉伟 · 陪伴／创业与职场”，具体文字是候选。无需向用户展示代码或长标签列表，不自动替换已确认个性签名。

每项专业特长要明确：擅长的具体环节、有依据的经验/资料、能完成的任务、不能承诺的范围。专业能力状态与人物角色设定分别记录；检索和实际回答读取相同配置，不把尚未接入的教学/实时能力显示为可用。

## 保持同一个人物与同一段关系

两条交互线共用同一套熟悉/好感/信任/舒适和有效记忆；专业任务另外记录目标、进度和提醒。专业互动按真实证据影响关系，没有“副线不计好感”规则，也不固定每次专业问答加分。专业指导的必要内容不受低信任限制，私人披露继续按关系阶段。

讲专业时保持性格，复杂问题可以给足步骤，话少不等于答案残缺；闲聊时不强行插入教学。主体验不决定恋爱资格、吸引或自动关系升级，是否允许恋爱与匹配条件独立设置，用户可以不选择恋爱。

后续按主体验安排代表场景，再逐人明确专业特长的可教范围；不为每一位重建完整 Skill。原基座、模块和人物差异继续复用，用户认可的新设定和助手候选分别保存。
