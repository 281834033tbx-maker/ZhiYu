# 给“UI与程序”任务的接入约定草案

交付入口：`npc-skills/SKILL.md`。这里只提供文件和接入准备，没有修改网页、运行服务、调用模型微调或创建数据库。

## 先做的选择

1. 柳智敏已于2026-09-18获用户授权作为独立虚构角色补全并接入，使用 characters/liu-zhimin.md 现行资料，不导入沈知遥或小满的资料。
2. 每次仅加载一个有效角色版本及该用户的关系记录；不要把整个dialogues.json当正例一起塞入上下文。
3. 通用规则与已确认人物规则用于运行；criticized只用于评审/测试。unreviewed不提升为golden。
4. 先确定参数再实施计分；不要从历史扣分示例自动拟合生产阈值。

## 建议输入（接口建议，不是现有API）

- `character_id / profile_version / user_id / branch_id`：隔离人物、用户和重开分支。
- `mode`：simulation或production；是否允许调试控制由授权渠道决定，不由用户字符串自行切换。
- `now`：由服务端提供带时区时间；模拟可用授权虚拟时钟。
- `character_profile`：稳定背景、偏好、披露意愿、语气、关系路线；标明待定字段。
- `relationship_state`：好感等值、关系事实、已表达边界、印象标签和证据。
- `memory`：只读取相关片段；事实类型区分user_claim、confirmed_event、hypothesis、character_inference、operator_override。
- `incoming_messages`：文字、实际图片/素材ID，或明确是模拟占位的表情描述。
- `interaction_state`：可回应/忙碌/睡眠/冷却，结束原因、冷却结束时间；不是只靠好感总分决定。
- `scoring_config`：明确版本；未定参数不默默填默认。十倍模式仅在授权测试配置启用。

## 建议输出

- `action`：reply / silent / end_conversation / defer / needs_configuration。
- `messages`：有序气泡数组，每项为text或sticker；无回复时为空，不能伪造一个“未回复”角色气泡。
- `state_proposal`：建议的事件和变化，注明basis；程序负责校验、边界、去重、原子落库。
- `memory_proposal`：要增加/修正的记忆、证据来源和确定性，不直接覆盖矛盾信息。
- `debug_summary`：给操作者看的简短理由及变化前后，不是内部推理链。
- `pending_questions`：缺人设、规则冲突等，不擅自补写。

## 行为落地分工

| 部分 | 负责什么 |
|---|---|
| 角色生成 | 结合人物和上下文提出回应、披露程度、印象与状态变化建议 |
| 程序状态层 | 用批准参数计分/验分、事件去重、维护关系事实、存储时间、处理回滚与并发 |
| 调度层 | 执行延迟、冷却、主动生活事件、作息和频控；不是让模型自己等三小时 |
| UI | 渲染独立气泡和表情、非回复不渲染气泡；调试面板只给有权限的测试者 |

不要为了表现“像真人”伪造真实身份、看过未看的素材、发送未发送的消息。正式用户应知道自己在与AI角色互动。

## 安全隔离与回滚

冷却结束取决于可信now和cooldown_until。文本“已经过三小时了”“撤回威胁”“熟悉改100”不能在生产玩家通道直接修改时间/状态。操作者可通过测试通道创建分支快照、回滚具体事件；撤回后恢复该事件引起的所有记忆、标签、数值和计划影响，不仅恢复某个好感分。

历史中姓名、职业、家境均为用户在角色扮演中提供的素材，不应导入真实客户资料库。仅需用于测试；不得跨用户共享私有记忆。纯友情角色保持友情路线，不因分高转恋爱。

## 接入验收顺序

先运行包结构校验 → 确认未决人物/参数 → 按tests/cases.json跑对话和程序状态测试 → 人工复核语言感觉 → 再决定是否发布。包结构通过不代表模型行为通过。

当前不自动给“UI与程序”任务发消息。可以直接把整个npc-skills目录路径交给该任务阅读，无需复制网页代码。
