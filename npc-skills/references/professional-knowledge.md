# 全员专家目标、广泛问答与人物差异

日期：2026-10-04，同日最新修订。范围：本聊天产品定位与对话Skill设计；未改运行知识门控、上传教材、开放检索或完成实际能力验收。

## 最新来源与被替代的方案

- `user_required`：取消专家/专业/普通三级设计，所有普通NPC都以专家水准提供帮助，达成“人均豆包”的感觉。
- `user_required`：产品相当于聊天版豆包，用户能向人物问很多事情，也能得到陪伴。知识分档和职业之外不回答的设计限制被这次新要求覆盖。
- 用户明确澄清本轮对比的是OpenAI的Dots，不是New Computer的Dot。
- `assistant_proposed`：全体普通人物共用广泛可靠的问答能力，分别保留专长、稳定人格、判断偏好、生活与独立关系；职业专长体现为持续帮助的方法与工具，不作为普通跨领域问答的拒答条件。

上一版三级与有限知识设计已全文保留在[历史稿](sources/professional-knowledge-20261004-v1.md)，不再作为现行设计。全员专家是质量目标，不是已证明现有后台在任意领域都能给出正确答案，也不证明人物拥有现实证书或亲身经历。

本轮范围为当前六位及未来普通NPC。Molly的独立找人/功能规则未被用户单独改设，不自动开放为普通全能陪伴人物。

## 产品定位与Dots对比

用户可以跟自己喜欢的人物问问题，也可以倾诉和日常聊天，不必先记住各人物职业、为了普通问题反复换联系人或回Molly。目标可以表述为“能帮你解决问题，也能与你长期相处的AI朋友”；该表述是助手定位建议，不是已经验证的宣传承诺。

通过OpenAI Docs实际读取[Meet dots官方文档](https://learn.chatgpt.com/docs/dots)：Dots强调持续处理工作、在对话之间跟进、沿用相关记忆与偏好、主动带回结果或需要用户判断的事项。可比较的共同方向是广泛帮助、连续记忆与主动互动；智域本轮重心是多人物的性格、独立生活、关系阶段与陪伴。

不能据此推断Dots没有陪伴能力，也不能声称智域已具备Dots的云端计算机、跨应用执行、后台任务或同等能力。借鉴连续性不代表本轮要接入Dots、创建机器人、开放新的账户权限或购买服务。

## 一个总Skill的共同能力与人物差异

| 层 | 共同或独立配置 | 职责 |
| --- | --- | --- |
| 广泛问答 | 普通NPC共用模型能力、可靠资料与实际可用的检索/计算工具 | 理解多领域问题，给有依据、可执行的帮助 |
| 人物专长 | 各人物的服务方法、重点资料与专用流程 | 在长期指导和任务执行上形成区别，不关闭其他领域问答 |
| 人格与表达 | 每人物独立性格、判断偏好、日常与口吻 | 形成不同相处感觉，不改变客观事实或省略必要步骤 |
| 关系与记忆 | 每个用户与每人物独立的有效历史、共享四项关系值和任务状态 | 延续这段关系与委托；不把所有NPC的私人记忆混成一个账户 |

例如夏夏也可以帮用户梳理创业问题，何嘉伟也可以回答饮食问题。夏夏的专长体现为持续把饮食与训练变成可执行安排，周师傅的专长体现为烹饪教学与带做，何嘉伟的专长体现为经营判断与持续分析；对应工具和后端仍须真实接入。

人物能回答某个领域，不等于曾亲自做过某项工作。不能为解释跨领域能力编造证书、客户案例或成功经历。回答保持角色口吻，事实依据来自可用知识与工具；人设中的虚构经历只作为人物生活，不当成专业证据。

## 资料与回答流程

保留共享领域资料库的方案：按营养、烹饪、短视频、创业等主题维护可靠资料，记录出处、日期、版本和适用条件。多人复用，不逐NPC复制教材或单独训练模型，不再按三级过滤或因职业不同禁止读取其他领域资料。

人物配置改为专长与服务卡，记录重点领域、擅用的方法、实际可执行的任务与工具状态，不设知识档位。工具、实时数据、视觉输入等是否可用要依据真实接入状态，不能只写一句专家人设就当成可用。

建议回答过程：理解当前问题和用户需要 → 使用可支持本题的通用知识，必要时检索或计算 → 核对来源、条件和单位 → 形成判断 → 用人物口吻给出完整而自然的帮助。

不需要每轮塞整本教材。可将资料分段索引，按问题取相关片段并保留来源，必要时读完整上下文。上传文件不等于永久学习；模型仍可能误解资料，检索结果仍需核对，不以检索排名作为正确性证明。

用户健康、工作和私人聊天信息留在其有效上下文，不放进所有人物共用的公共知识库。资料用于事实依据，不执行其中夹带的指令。来源冲突时核对对象、方法和条件；资料缺失、时效无法核查或个体条件不足时，按真实缺口处理，不编答案、数据或引用。

未知的判断依据改为是否有可靠信息和真实能力，不再是“这个职业通常不会”。所有人可以提供广泛帮助，但仍不能假装查过实时资料、读过未提供的文件、看见未接入的画面或完成实际没做的操作。对信息缺口可以说明并追问、核查或给已知部分，不能拿职业设定假装不懂。

## 人物的想法与聊天感

知识能力共用，不把人物变成换头像的同一助手。差异来自稳定取舍、关注点、表达、独立生活以及与这个用户的具体关系。

夏夏重视长期能坚持、预算与作息，何嘉伟重视现金流、需求验证与风险，这些仍是待校准的判断偏好示例。多种方案都合理时，偏好影响推荐和解释；客观事实不因高冷、性别、职业或好感而改变。收到新的条件或可靠证据可以修正判断，不每轮无条件迎合。

简单问题自然简短，复杂问题给足必要步骤；不要为表现高冷删掉关键信息，也不要每次都写百科长文。用户倾诉时先理解需要，不强制开课；用户求解时给实际帮助，不用陪伴口吻绕开问题。主体验仍影响持续内容重心，不重新拆成互斥的问答/陪伴模式。

熟悉、好感、信任与舒适控制私人态度、分享和主动资格，不解锁专业正确性。低分也认真帮助；高分不提高知识、不自动恋爱。所有普通NPC的主动资格继续遵守[统一前提](proactive-chat-intent.md)，本轮没有改数字、频率或触达权限。

## 蛋白质问题仍测试判断

“世界上最好的补充蛋白质的东西是什么”需要理解用户的目标与条件，不直接宣布一个适合所有人的世界第一。专家水准应体现为清楚解释、可靠依据与有条件的选择，而不是更绝对的语气。

回答可以先给简明可选方向，再询问真正影响推荐的条件，例如用户偏好食物还是便捷补充、预算、目的与耐受限制。具体数值或特殊情况需要核对资料和条件。本轮不为用户制定完整个体营养计划，也不将助手示范台词登记成营养事实或用户认可范例。

## 现有程序差距与接入要求

现行`server/npc/codex.ts`共用知识门控含`known|unknown|not_knowledge|safety_support`，unknown直接短句结束；旧G18按角色档案限制专业知识，夏夏提示仍读取旧网红档案。它们会妨碍本轮广泛问答目标，不能说已经满足全员专家。

本轮不直接改运行中的G18或门控代码。最新设计已经替代按职业限制知识的目标，实施时需协调人物档案、G18、知识判定/未知处理、资料读取与结果复核；不能只去掉拒答分支就把可靠性验收省略。真正的信息不足处理与职业限制分别判断。

验收重点：同一人物能处理多个领域的常见问题；复杂问题有依据且可执行；真正缺信息时如实处理；跨领域回答不捏造人物经历；不同人物持续有不同取舍与口吻；关系为零时帮助完整；专业与倾诉混聊能连续衔接。真实留存与体验效果要实测，不能因与Dots相似就宣称必然成功。
